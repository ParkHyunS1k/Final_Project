# Val 셋 (개발용)

**여기 있는 건 전부 Val이다. Test가 아니다.** 프롬프트·threshold·checkpoint 선택은 여기서만 한다.
Test를 보고 고치면 그 순간 Test가 개발셋이 된다(docs/eval.md).

## agent_pilot.jsonl

프롬프트 개발용 파일럿 12건. **정식 테스트셋이 아니다.**
- 라벨이 `{decision, tool}`뿐이다. 인자까지 채점하지 않으므로 Full Call Accuracy를 잴 수 없다.
- 12건은 통계적으로 무의미하다. 이 파일의 결과를 수치로 인용하지 마라.
- 용도는 하나다: 프롬프트를 고쳤을 때 **무엇이 고쳐지고 무엇이 깨졌는지** 눈으로 보는 것.

실행:

    py -3 scripts/chat.py --smoke

DB는 `server/db/fixtures.py`의 데모 시드를 쓴다. 업무 id(`t_eval`, `t_api`, `t_db` 등)와
팀원 이름(김현민/이성경/박지원/최지원)이 이 시드에 묶여 있으므로 시드를 바꾸면 라벨도 바꿔야 한다.

### 기록

**모델이 중간에 바뀌었다.** `gemini-2.5-flash`의 무료 일일 한도(20회)를 v1+v2 실행으로 소진해서
v2.1부터 `gemini-3.1-flash-lite`로 옮겼다. **모델이 다른 행끼리는 비교하지 마라.**

| 프롬프트 | 모델 | 결과 | 무엇이 바뀌었나 |
|---|---|---|---|
| agent-v1   | gemini-2.5-flash      | 9/12 실행, 6 일치 | — |
| agent-v2   | gemini-2.5-flash      | 9/12 실행, 8 일치 | 업무 목록 컨텍스트 + search-then-act + 완료 표현 → p-05·p-06 고침, **p-04 깨짐** |
| agent-v2.1 | gemini-3.1-flash-lite | 12/12 실행, 10 일치 | 사람 이름 모호성 규칙 강화 → p-04 고침 |
| agent-v2.2 | gemini-3.1-flash-lite | 12/12 실행, **11 일치** | create vs update 구분 규칙 → p-01 고침 |

v1·v2는 쿼터 때문에 12건을 다 못 돌렸다(429). 같은 모델(2.5-flash)에서의 v1→v2 비교만 유효하다.

### 남은 불일치: p-10

"확인 카드 UI 누가 하고 있지?" → 모델이 `search_tasks`를 부르지 않고 컨텍스트만 보고 `no_tool`로 답한다.
**모델이 틀렸다기보다 라벨이 애매하다.** 컨텍스트에 업무 목록(담당자 포함)을 넣은 순간
"조회 Tool을 반드시 불러야 하는가"의 정답이 흔들린다. 결정이 필요하다.

- (a) 컨텍스트 유지 + 라벨에 `acceptable_calls` 도입 — 컨텍스트로 답할 수 있으면 `no_tool`도 정답
- (b) 컨텍스트에서 업무 목록 제거 — 조회 Tool 사용이 항상 정답이 되지만 모든 변경이 2-step이 되고
  API 호출이 2배가 된다(v1에서 실제로 되묻기 회피가 났던 원인)

**이 결정 전에는 No-Tool Accuracy를 계산하지 마라.** 정답 정의가 없다.
