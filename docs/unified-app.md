# ProjectMate 통합 앱 · 2026-10-08

CareerFlow는 별도 서비스 버튼이 아니라 ProjectMate 안의 개인 역량·기회·경험 관리 기능으로 통합한다. 기존 Python CareerFlow와 원본 개인 저장소는 변경하지 않았다. 그 SQLite 자료는 자동 이관하지 않는다.

## 진입과 화면

```text
/ 랜딩
  └ 시작하기 → /app 통합 홈
      ├ 공개 모집 팀 · 받은 초대 · 내 프로젝트 · 오늘 체크인
      ├ 프로젝트 찾기: 역량 기반 추천 · 20개 템플릿 · 범위 슬라이더
      ├ 내 프로젝트: 기존 진행 현황 · 실제 업무 · 초대 · 역할 추천
      ├ 공고 찾기: 직무별 외부 검색 · 개인 공고 보관함 · 역량 비교
      └ 마이페이지: 이력서·역량 / 포트폴리오 / 경험·성장 기록
```

루트는 프로젝트를 가지고 있어도 랜딩을 보여준다. 명시적인 옛 초대·프로젝트 링크(`/?invite=…`, `/workspace?project=…`, `/career?project=…`)는 깨뜨리지 않고 통합 앱의 해당 화면으로 이동한다. 로고와 서비스 소개는 랜딩으로 돌아간다.

| 필수 결과물·완료 기준 입력 제거 | 새 템플릿 프로젝트에는 별도 입력과 결과물 승인 절차가 없다. 실제 진행 업무의 완료·근거로 완료를 기록한다. 빈 프로젝트는 완료 보상을 받지 못한다. |

| 진입 시 활성 팀 목록 | 홈에서 공개 모집에 동의한 준비·진행 중 팀을 조회한다. 실제 DB 자료이며 가짜 팀이나 인원은 생성하지 않는다. |
| 클릭형 팀 합류 | 이름·로그인 이메일 공유 동의 → 참여 요청 → 팀장 초대 → 신청자 홈의 받은 초대 → 목표 동의 후 합류. 관심 요청만으로 비공개 프로젝트 접근권한이 생기지 않는다. |
| 시간이 흐르는 시각적 표현 | 홈의 실제 시작·마감 기반 진행 막대와 프로젝트의 기존 카운트다운. 장식 회전 효과는 모션 줄이기 설정을 존중한다. |
| 등급·배지·공유 | 한국 날짜 기준 학습 체크인, 연속 학습일, 기록 점수·레벨·배지, 본인이 눌러 복사하는 공유 문구. 실력 인증이나 채용 등급으로 표시하지 않는다. |
| 공부 여부 체크 | 홈의 오늘 체크인: 공부함 / 막힘 / 휴식. 같은 날 중복 점수 없음. 자동 학습 감시·알림 발송은 아직 없다. |
| 이력서 + 포트폴리오 | 개인 포트폴리오 링크·본문·PDF/TXT 추출 자료를 저장하고, 선택한 본문을 이력서 분석 입력에 합친 뒤 검토·저장한다. 링크만으로 코드 분석했다고 표시하지 않는다. |
| 공고와 프로젝트 연결 | Jooble API로 직무와 지역에 맞는 공고를 검색하고 원문 링크를 확인한다. 관심 공고를 저장해 이력서의 목표 공고로 가져온 뒤 요구 역량을 비교하고 프로젝트 추천으로 이동한다. |
| 결과물 이해도 질문·GitHub 분석·비용 절감 | 아래 다음 단계 설계. 이번 구현에 실제 저장소 수집이나 AI 구술 평가를 포함하지 않는다. |

## 현재 데이터 파이프라인

1. 개인 자료: 이력서, 포트폴리오 본문, 목표 공고를 사용자가 확인한다. 포트폴리오를 합치는 것은 초안 편집이며 자동 저장·외부 AI 전송이 아니다.
2. 역량 비교: 기존 기본 추출 또는 별도 동의를 받은 AI 분석으로 원문 근거를 찾는다. ‘근거 없음’은 ‘능력 없음’과 다르다.
3. 프로젝트 추천: 개인 강점·성장 목표·공고의 요구 역량을 20개 템플릿과 비교한다. 범위를 줄이면 포함된 업무와 역량도 달라짐을 명시한다.
4. 시작: 선택한 템플릿과 범위를 보존하고 실제 업무를 생성한다. 우선 생성자에게 배정하며 타이머는 별도의 시작 버튼으로 시작한다.
5. 협업: 팀원은 공유할 역량만 선택한다. 역할안은 저장된 범위 안에서 생성되고 사람이 승인한다. 같은 과제를 중복 생성하지 않는다.
6. 성장: 실제 본인 업무의 완료 근거를 확인해 경험으로 가져온다. 경험이 무효가 되면 추천·공유 근거와 점수에서 제외한다.

## 기존 프로젝트 보존

- 새 `project_policy.min_members` 기본값 2와 `completion_mode` 기본값 `deliverables`는 기존 규칙을 보존한다.
- 통합 템플릿 생성 경로만 `min_members=1`, `completion_mode=tasks`를 사용한다. HTTP 본문으로 임의 정책을 덮어쓸 수 없다.
- 기존 팀의 결과물·동의·완료 기록, 이전 7일 기한은 변경하지 않는다. 새 프로젝트도 7일 기한은 유지한다.
- 기존 `/api/career` 생성 경로는 호환 목적으로 남는다. 통합 UI 생성은 `/api/hub`의 `createTemplate`을 사용한다.

## 저장·공개 범위

- `hub_records`: 계정별 포트폴리오, 공고, 날짜별 체크인. 자료 종류별 최대 100개, 포트폴리오/공고 본문 최대 20,000자. 편집은 가능하지만 삭제 UI는 미구현이다.
- `hub_projects`: 선택된 템플릿 스냅샷, 범위, 솔로/팀 모드, 모집 공개 여부. 기본 비공개다.
- `hub_interests`: 참여 요청자의 이름·로그인 이메일(명시적 동의), 초대 연결. 팀장만 요청자 연락처를 보고, 유효 초대 토큰은 그 요청자에게만 반환한다. 공개 팀 목록에는 포함하지 않는다.
- 세 테이블 모두 RLS ON, 공개 REST 정책 없음. 인증된 서버 경로에서만 접근한다. 실제 초대는 기존 이메일 검증·권한·기한·revision·최대 인원 검사를 재사용한다.
- 새 템플릿 생성과 업무·의존관계·링크 저장은 한 트랜잭션이다. 동일 요청 재시도는 같은 프로젝트를 반환한다.
- 배지는 개인 기록 활동을 나타낸다. 학습 체크인은 자기 보고이며 실제 공부 여부를 독립적으로 검증하지 않는다. 학습일 10점, 현재 유효한 경험 30점, 100점마다 레벨 1 증가.
- 공개 주소는 HTTPS·인증 정보 없음만 허용한다. 서버가 해당 주소를 가져오거나 저장소 코드를 실행하지 않는다.

## 다음 단계: 포트폴리오 검증 루프

```text
공개 저장소 선택 + 분석 동의
  → 제한된 README·구조·선택 파일 읽기 (코드 실행 없음)
  → 파일 경로·커밋·줄 범위를 가진 근거 카드
  → 내가 담당한 부분 선택
  → 근거 카드에 연결된 짧은 설명·대안·테스트 질문 3개
  → 답변과 구현 비교, 확인된 내용 / 추가 설명 필요 분리
  → 보완할 학습 과제 + 다음 체크인
  → 사용자 확인 후 포트폴리오·이력서 경험 갱신
```

비용은 먼저 모델 밖에서 줄인다. 생성은 검토된 템플릿을 사용하고, 저장소는 파일 수·크기·토큰 수 상한을 둔다. 파일 해시/커밋별 캐시와 변경분 갱신, 심볼·README 중심 검색으로 관련 부분만 보낸다. 요약에도 근거 위치를 남겨 원문으로 돌아갈 수 있게 한다. 짧은 요약·질문은 저비용 단계, 불확실한 검증만 별도 추론 단계로 분리한다. 사용자별 일일 호출·토큰 예산을 두며 전체 저장소를 매번 재전송하지 않는다. 특정 ‘루나’ 도구 도입은 정확한 제품·라이선스·데이터 처리 조건을 확인한 뒤 결정한다.

답변의 문장 유사도나 깃허브 커밋 수만으로 실력을 인증하지 않는다. 팀 결과물 전체를 개인 기여로 인정하지 않는다. 저장소·문서의 명령문은 분석 대상 데이터이며 시스템 지시로 실행하지 않는다. 비밀·바이너리·외부 네트워크·임의 코드 실행은 기본 제외한다. 비공개 저장소와 외부 AI 전송은 별도 동의와 최소 권한이 필요하다.

후속 우선순위는 개인 자료 삭제와 보존 정책, 저장소 근거 카드와 이해도 질문, 동의 기반 주간 회고 알림, 공고 검색 호출량 관리다. 외부 출시 전에는 실사용 인증과 초대 이메일 설정, 데이터 보존과 삭제, 비용 및 남용 제한을 별도 점검해야 한다.

## 2026-11-02 업로드 검증

- 공고 검색: 로컬 통합 앱에서 Jooble에 `개발자`, `서울` 조건으로 요청해 총 101건과 첫 페이지 10개 표시를 확인했다. 공고 수와 내용은 검색 시점에 따라 달라진다.
- 서버 전용 `JOOBLE_API_KEY`는 `web/.env.local`에 둔다. 키 파일, 로컬 DB, 개인 PDF와 학습 데이터는 Git에서 제외한다. 저장소의 `.env.example`에는 변수 이름만 포함한다.
- `npm test`: 264개 통과. `npx tsc --noEmit`: 통과.
- `local-llm`의 Python 테스트: 11개 통과. 모델 학습과 앱의 로컬 LLM 교체는 아직 실행하지 않았다.
- `npm run lint`: 기존 UI 구성요소와 테스트 코드의 규칙 오류로 실패했다. 이번 확인에서 새 서비스 파일의 린트 오류는 보고되지 않았다.
- 작업 브랜치는 `codex/career-growth-pipeline`이다. 확인한 원격 `main`은 `96c7672`이며 이 작업의 시작 커밋보다 36개 앞서 있다. 운영 반영 전에 양쪽의 팀 기능과 DB 변경을 통합해야 한다. 특히 원격의 `0005_team_join.sql`과 이 브랜치의 `0005_career_growth.sql`, 마이그레이션 메타데이터를 조정해야 한다. 공유 운영 DB에 이 브랜치의 마이그레이션을 그대로 적용하지 않는다.

## 로컬 실행

`projectmate-integration/web`에서 실행한다. 기존 미리보기 서버를 먼저 `Ctrl+C`로 끈다. DB 잠금 파일을 지우거나 DB 폴더를 삭제하지 않는다.

```sh
env -u DATABASE_URL DATABASE_PATH=.data/career-preview npm run db:migrate
DATABASE_URL='' DATABASE_PATH=.data/career-preview AUTH_DEV_HEADERS=1 OPENAI_API_KEY='' EMAIL_PROVIDER='' EMAIL_FROM='' EMAIL_API_KEY='' npm run dev -- --webpack --port 3276
```

별도 터미널(로컬 가상 계정 체험 전용):

```sh
node scripts/dev-as.mjs 3277 career-preview-owner 가상지원자 3276
```

브라우저 시작 주소는 **http://127.0.0.1:3277/** 이다. `/app` 직행은 통합 홈을, `/`는 랜딩을 연다. 이미 프록시 3277이 실행 중이면 다시 실행하지 않는다. 가상 계정은 운영 로그인과 다르며 운영 모드에서 개발 헤더는 무시된다.

새 마이그레이션: `0006_unified_hub.sql`, `0007_team_interest_invitations.sql`. 기존 `0005_career_growth.sql` 이후 순서대로 적용한다.
