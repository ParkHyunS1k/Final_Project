# 현재 개발 스프린트

2026-09-09 설계 합의: [집중 스프린트 설계](superpowers/specs/2026-09-09-spartan-sprint-design.md). 최소 2인 시작, 시작 후 목표·기한 고정, 결과물 기준 완주, 개인별 가용시간 입력 제거, 사용자 승인형 AI 변경안, 마감 연동 이메일 독촉을 정의했다. **아직 코드에 반영하지 않은 구현 전 설계**이며, 아래 내용은 기존 버전의 구현 이력이다. 향후 제품 변경은 새 합의를 기준으로 진행한다.

목표: 실제 상태로 복구안을 만들고, 승인한 계획을 다시 접속해도 유지한다.
제품 결정자: 사용자. 이번 구현 담당: Codex. 실제 서비스 운영팀의 담당자·가용시간·출시일은 아직 확정하지 않았다.

| 작업 | 확인할 동작 | 상태 |
|---|---|---|
| 서비스 목적 문서 통일 | 연구가 출시 조건으로 남지 않음 | 반영 |
| 서버 상태 저장 | 로그인 계정별로 다시 조회 가능 | 구현·검증 완료 |
| 체크인·날짜 가용시간 | 입력 변경으로 실제 계산 변화 | 구현·검증 완료 |
| 복구안·승인 | 최신 상태 검증·중복 승인 차단 | 구현·검증 완료 |
| 결과물 근거·기록 | 완료 근거와 변경 기록 유지 | 구현·검증 완료 |
| 통합 확인·비공개 배포 | 저장·충돌·격리 테스트와 빌드 | 검증·비공개 배포 완료 |

후속 작업에서 프로젝트 생성·목표 합의·초대 링크·권한을 구현했다(아래). 후속 4단계에서 업무 생성·담당자 배정도 구현했다. 다음 범위: 실제 두 계정 초대 검증과 한 팀의 스프린트 운영. 실제 결제·환급은 정책과 검토 흐름을 정한 후 진행.

## 결정 기록

- 2026-09-08: 사용자 결정 — 연구가 아니라 서비스 개발이 목적.
- 2026-09-08: 배포 환경이 Workers이므로 실제 파일럿 API는 web/에서 구현하고 D1을 사용. 로컬 Python 서버를 외부에 노출하는 임시 터널은 사용하지 않음. Python 구현은 보존하며 웹과 자동 동기화된다고 가정하지 않음.
- 2026-09-08: 실제 금전 처리·팀원 초대는 이번 작업 범위에서 제외. 계정별 샘플 프로젝트로 지속 상태와 복구 흐름을 검증.

## 검증 기록

- 일정 단위 테스트 10개 + 실제 API 핸들러/SQLite 통합 테스트 4개 통과.
- 실행 중인 로컬 Workers + D1에서도 참여·체크인·복구안 승인·재조회 통과.
- 타입 검사, 서비스 코드 린트, 프로덕션 빌드 통과.
- 웹 브라우저 상호작용 테스트와 실제 팀 다중 계정 협업은 이번 검증에 포함하지 않음.

- 비공개 배포 v2 성공: https://projectmate-sprint-demo.heoysik2.chatgpt.site
- 배포 API는 사용자 식별 헤더가 없는 접근에 401을 반환함을 확인. Sites 접근 우회 토큰은 사용자 로그인 정보를 제공하지 않아, 실제 로그인 세션의 운영 API 읽기·쓰기는 이 자동 점검으로 검증하지 못함. 로컬 로그인 + D1 저장 흐름은 검증 완료.

## 후속 1~3단계 — 2026-09-08

- 실제 로그인: 운영 브라우저의 기존 체크인과 버전이 새로고침 후 유지됨을 확인.
- 프로젝트 생성: 목표·시작일·7~10일 기간·필수 결과물·완료 기준·확인 동의 저장. 프로젝트 전환 지원.
- 팀 초대/권한: 이메일 지정 링크·7일 만료·취소·목표 확인 후 수락. 최대 4명, 팀원별 데이터 수정 제한, 팀장 최종 승인.
- 검증: 일정 10개 + API 통합 6개 통과. 동시 가입·슬롯 고유성·비멤버 접근·팀원 권한·만료/취소 포함. 타입·린트 통과.
- 로컬 브라우저: 7일 프로젝트 생성·새로고침 유지·초대 링크 생성/취소 확인.
- 실제 외부 계정 검증 대기: 초대할 이메일과 해당 계정 로그인 필요. 현재 Sites 소유자 전용 접근도 별도로 설정해야 함.
- 신규 프로젝트의 업무 생성·배정은 미구현이며 다음 단계로 명시. 자동 결제·환급 없음.

## 후속 4단계 — 2026-09-08

- 이전 v3 비공개 배포 성공 확인. v4 배포 후 운영 로그인 계정으로 기존 프로젝트·체크인 조회와 실행 계획의 업무 추가·편집 버튼 표시 확인. 운영에서 신규 업무 쓰기와 두 계정 협업은 별도 검증 대상.
- 팀장 업무 생성·편집: 이름, 참여 멤버 담당자, 남은 공수, 필수/부가 여부, 선행 작업. 날짜별 가용시간 편집과 일정 재계산 연결.
- 검증: 일정 10개 + API 통합 9개 통과. 비멤버/팀원 편집 제한, 순환·자기 참조·잘못된 입력 거절, 동시 쓰기 충돌, 업무/의존관계/이력 롤백 포함.
- 로컬 브라우저: 업무 2개 생성 → 선행 작업 선택 → 가용시간 2h로 9–10시/10–11시 배치 → 업무 공수를 0.5h로 편집 → 10시 30분 종료 → 새 접속 후 유지 확인.
- 편집 창을 연 시점의 버전으로 저장하여 자동 새로고침 중 다른 변경을 덮어쓰지 않도록 보호.

- 실제 외부 계정 협업: 초대 이메일과 계정 로그인, Sites 외부 접근 설정이 필요해 미검증. 다음 단계는 한 팀의 실제 스프린트 운영.

## 노션형 작업 공간 1차 — 2026-09-08

- 사용자 방향: 노션의 익숙한 페이지·업무 관리 경험에 7~10일 프로젝트 완주 컨셉을 결합. 이번 범위는 사이드바, 표·보드, 업무 상세 패널. 자유 문서 편집은 다음 단계.
- 기본 화면을 프로젝트 업무로 변경하고 큰 소개 영역을 제거. 사이드바에서 프로젝트·내 할 일·현황·문서·팀 가용시간·완주 확인 이동.
- 동일한 업무를 표와 상태별 보드로 표시. 담당자 배정은 팀장, 상태·설명·공수·체크인은 팀장 또는 담당자가 수정. 완료는 근거 입력 후 기록.
- 상세 패널에서 설명·선행 작업·체크인·완료 근거 조회와 저장. 문서 메뉴는 현재 합의한 목표·결과물·완료 기준 조회와 초대 관리.
- 기존 데이터 보존을 위해 status(todo/in_progress), description 필드만 추가하는 0004 마이그레이션 생성·로컬 적용. done/deferred 값과 결과물 근거 유지.
- 테스트 21개 통과. 로컬 화면에서 표 상태 변경→보드 이동 반영, 상세 설명·공수 저장→재접속 유지, 체크인 저장→상세 재조회, 근거 입력→완료 상태·진행률 반영 및 모바일 사이드바 이동 확인.
