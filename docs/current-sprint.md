### 확정한 규칙 (구현 반영)

- 마감 = 시작 시각 + 선택한 7~10일. 마지막 날 18시 고정 규칙은 폐기했다.
- 유효 상태는 서버 시각으로 판정한다. 저장된 상태가 `active`여도 마감에 도달하면 종료다.
- 완주는 시작 시 고정한 결과물의 팀장 확인만으로 판정한다. 보고 횟수·업무 수는 조건이 아니다.
- 개인별 가용시간 입력은 없다. 전원 하루 8시간은 내부 계산 가정이며 근무시간 기록이 아니다.
- 목표 축소·기한 연장·부가 업무 보류·다음 스프린트 이월은 어떤 경로로도 제공하지 않는다.
- 이전 규칙으로 만든 프로젝트는 자동 전환하지 않고 열람·내보내기만 유지한다.

### 검증 기록

- 자동 테스트 91개 통과: 일정·공수 16, 정책 14, 알림 계산 12, 가드레일 2,
  API 통합 16, 알림 통합 13, 변경안 통합 18. 실제 API 핸들러 + SQLite를 사용한다.
- 타입 검사, 서비스 코드 린트, 프로덕션 빌드, 로컬 D1 마이그레이션(0005~0007) 적용 통과.
- 기존 UI 카탈로그(`components/ui/*`)의 린트 오류는 이번 변경 이전부터 있던 것이다.
- 로컬 개발 서버는 모의 로그인만 제공하므로 **브라우저 화면 흐름과 두 계정 협업은
  이번 자동 검증에 포함되지 않았다.**

### 남은 문제

1. **실제 이메일 발송 미검증.** 제공자·발신 도메인·API 키와 외부 정기 실행기 등록이 필요하다.
   현재 배포 경로에는 예약 실행 진입점이 없다. 절차: [운영 문서](reminders-operations.md).
2. **운영 AI 모델 미연결.** 가짜 모델로 전체 흐름만 검증했다. 프롬프트 품질은 평가하지 않았다.
3. **실제 두 계정 검증 미완료.** 초대·목표 합의·승인·완주를 사람이 직접 확인해야 한다.
4. **이전 규칙 프로젝트의 명시적 전환 미구현.** 현재는 읽기 전용 보존만 한다.
5. **가드레일 평가의 한계.** 형식·권한 검증만 측정했다. 대상 선택의 옳고 그름은 사람이 본다.
   근거: [평가 보고서](../evals/change-review/2026-09-09/REPORT.md).

## 결정 기록

- 2026-09-08: 사용자 결정 — 연구가 아니라 서비스 개발이 목적.
- 2026-09-08: 배포 환경이 Workers이므로 실제 파일럿 API는 web/에서 구현하고 D1을 사용. 로컬 Python 서버를 외부에 노출하는 임시 터널은 사용하지 않음. Python 구현은 보존하며 웹과 자동 동기화된다고 가정하지 않음.
- 2026-09-08: 실제 금전 처리·팀원 초대는 이번 작업 범위에서 제외. 계정별 샘플 프로젝트로 지속 상태와 복구 흐름을 검증.
- 2026-09-09: 사용자 확정 — 프로젝트 마감은 시작 시각 + 선택한 일수. 이메일 제공자 정보는 사용자가 제공 예정이며, AI는 이번에 가짜 모델로만 연결한다.
- 2026-09-09: 이전 규칙 프로젝트는 자동 전환하지 않고 읽기 전용 기록으로 보존한다. 명시적 전환 기능은 만들지 않았다.

## 검증 기록

- 일정 단위 테스트 10개 + 실제 API 핸들러/SQLite 통합 테스트 4개 통과.
- 실행 중인 로컬 Workers + D1에서도 참여·체크인·복구안 승인·재조회 통과.
- 타입 검사, 서비스 코드 린트, 프로덕션 빌드 통과.
- 웹 브라우저 상호작용 테스트와 실제 팀 다중 계정 협업은 이번 검증에 포함하지 않음.

- 비공개 배포 v2 성공: https://projectmate-sprint-demo.heoysik2.chatgpt.site
- 배포 API는 사용자 식별 헤더가 없는 접근에 401을 반환함을 확인. Sites 접근 우회 토큰은 사용자 로그인 정보를 제공하지 않아, 실제 로그인 세션의 운영 API 읽기·쓰기는 이 자동 점검으로 검증하지 못함. 로컬 로그인 + D1 저장 흐름은 검증 완료.

## 후속 1~3단계 — 2026-09-08

- 실제 로그인: 운영 브라우저의 기존 체크인과 버전이 새로고침 후 유지됨을 확인.
- 프로젝트 생성: 목표·시작일·7~10일 기간·필수 결과물·완료 기준·확인 동의 저장. 프로젝트 전환 지원.
- 팀 초대/권한: 이메일 지정 링크·7일 만료·취소·목표 확인 후 수락. 최대 4명, 팀원별 데이터 수정 제한, 팀장 최종 승인.
- 검증: 일정 10개 + API 통합 6개 통과. 동시 가입·슬롯 고유성·비멤버 접근·팀원 권한·만료/취소 포함. 타입·린트 통과.
- 로컬 브라우저: 7일 프로젝트 생성·새로고침 유지·초대 링크 생성/취소 확인.
- 실제 외부 계정 검증 대기: 초대할 이메일과 해당 계정 로그인 필요. 현재 Sites 소유자 전용 접근도 별도로 설정해야 함.
- 신규 프로젝트의 업무 생성·배정은 미구현이며 다음 단계로 명시. 자동 결제·환급 없음.

## 노션형 작업 공간 1차 — 2026-09-08

- 사용자 방향: 노션의 익숙한 페이지·업무 관리 경험에 7~10일 프로젝트 완주 컨셉을 결합. 이번 범위는 사이드바, 표·보드, 업무 상세 패널. 자유 문서 편집은 다음 단계.
- 기본 화면을 프로젝트 업무로 변경하고 큰 소개 영역을 제거. 사이드바에서 프로젝트·내 할 일·현황·문서·팀 가용시간·완주 확인 이동.
- 동일한 업무를 표와 상태별 보드로 표시. 담당자 배정은 팀장, 상태·설명·공수·체크인은 팀장 또는 담당자가 수정. 완료는 근거 입력 후 기록.
