# 안전고리·안전난간 탐지 학습 데이터 계획

스코프: 사전학습 모델이 존재하지 않는 **안전고리**와 **안전난간** 두 대상을 AI Hub 데이터로 직접 학습한다.
README 2절 9종 중 **B-안전난간 미설치**와 **D-안전대 부착설비 미설치/고리 미체결**에 해당한다.

법령 RAG는 **타 팀 전담**이다. README 5절 [6][7], 9절의 조항 정확도·환각률, 15절 2·3번은 이 문서 범위 밖.

> 이 문서는 **계획과 결정**을 담는다. 라벨 실측과 근거는 [`phase0_results.md`](phase0_results.md),
> 학습 결과는 [`train_results.md`](train_results.md)에 있다.

### 하드웨어

맥북(M3 Pro 18GB)에서 YOLOv8s / 640 / batch 16 을 실제로 돌려 **12.7 img/s**를 측정했다.
4070은 약 110 img/s로 8~9배다.

| 용도 | 하드웨어 |
|---|---|
| 라벨 파싱, YOLO 변환, 소규모 sanity run, 추론·데모 | 맥북 |
| **본 학습, 하이퍼파라미터 탐색, seed 반복** | RTX 4070 |

원천 38 GB는 4070 데스크톱으로 직접 받는다. `scripts/download_aihub.sh`는 bash + curl만
있으면 리눅스/WSL에서 동작한다. 맥북에는 라벨 0.76 GB만 있으면 분석이 전부 된다.

> README 7절의 RunPod 4090 300 GPU시간 예산은 탐지에 쓸 필요가 없다. **VLM QLoRA로 돌린다.**
> 4070 12GB로는 VLM 1.7B(16GB)·4B(24GB) 파인튜닝이 불가능하며 거기가 GPU가 필요한 지점이다.

### 1.3 71407 — 교차검증 전용

| 시나리오 | 클래스 | 개수 | 의미 | 쓰는가 |
|---|---|---:|---|---|
| `Y-04` | `SO-01` | 1,800 | 개구부 안전난간 설치 | **O** |
| `Y-05` | `SO-02` | 1,800 | 단부 안전난간 설치 | **X** |

> **`Y-05` 의 `SO-02` 는 쓸 수 없다.** 박스를 잘라 확인했다. 난간은 화면 상단에
> 걸쳐 있는데 **박스가 화면 전체를 덮는다** — 철근과 슬래브까지 전부 들어간다.
> 장면 영역 라벨이지 탐지 정답이 아니다. `class_mapping.yaml` 이 71407 의 `SO-02` 를
> 매핑하지 않은 것이 맞다. 71407 에서 안전난간으로 검증된 코드는 `SO-01`(개구부),
> `SO-04`(단부 청색패널), `SO-06`(비계) 세 개이고, 이 중 원천을 받아 둔 시나리오에
> 나오는 것은 `Y-04` 의 `SO-01` 뿐이다.
>
> `Y-04` 의 `SO-01` 은 개구부를 둘러싼 사각 파이프 난간을 타이트하게 잡은
> 정상 박스다. 다만 507 의 `SO-01`(비계에 길게 붙은 난간대)과는 **구조가 다른
> 물체**이고 실내 클로즈업이다. 낮은 점수가 나오면 탐지 실패인지 스케일·구조
> 일반화 실패인지 구분해서 읽어야 한다.

> **학습에 섞지 않는다.** 71407 `SO-01`의 면적 중앙값이 0.4513으로 507의 0.058과 8배 차이다.
> 난간을 클로즈업으로 찍어 스케일 분포가 완전히 다르다.
> README 6절의 "연출 데이터 두 종류 간 일반화를 잰다"는 목적에 맞게 **평가 전용**으로 쓴다.

**안전보조장비 파티션(`SO-35`, `SO-41`~`SO-47`)은 전량 제외.** 박스 확인 결과 라바콘,
경광봉, 방독마스크, 안전표지, 위험테이프 등 보조용품이며 안전난간·안전고리가 아니다.

## 2. 모델을 둘로 나누는 이유

Phase 0 교차표에서 확인된 사실이다.

```
             개구부  고소작업대   공통   로프   비계   사다리
SO-01 안전난간    0        0        0      0  58,614     0
WO-06 안전고리    0        0   36,454      0       0     0
```

두 파티션을 합쳐 단일 모델로 학습하면 **서로의 클래스가 라벨 없는 positive가 된다.**
공통 이미지에 안전난간이 찍혀 있어도 라벨이 없으므로 모델은 그것을 배경으로 학습한다.

클래스별 loss 마스킹으로 해결할 수 있으나 Ultralytics 기본 학습 루프는 지원하지 않는다.
**모델 2개로 분리한다.**

같은 이유로 **상황유형 필터도 필수다.** 같은 작업유형 안에서도 라벨 부착이 갈린다.

```
비계작업  UA 14,180프레임 → SO-01 0건 | UC 5,070 → 0건 | WS 6,916 → 6,464건
공통      UA 15,934프레임 → WO-06 4,041건 | WS 2,664 → 0건
```

거르지 않으면 19,250 프레임의 난간이 배경으로 학습된다.
`configs/data/targets.yaml`에 제약으로 박아 두었다.

## 5. 학습 클래스 설계 — A안의 전제가 깨졌다

> **`WO-06` 은 안전고리가 아니라 작업자의 몸통이다.** 원천을 확보한 뒤 507 공통 UA
> 프레임에서 `WO-06`(빨강)과 `UA-01`(파랑)을 겹쳐 그려 확인했다.
> `WO-06` 은 어깨~허벅지, 즉 **안전대를 착용하는 몸통 영역**이고
> `UA-01` 은 안전모부터 발끝까지의 **전신**이다. 고리를 잡은 박스는 어디에도 없다.
>
> 8절에 "고리 자체인지 부착부 전체인지"로 남겨 두었던 미해결 항목의 답은
> **둘 다 아니다**. 면적비 0.27배(실측 재확인 0.0105 대 0.0323)는
> "고리 대 사람"이 아니라 **"몸통 대 전신"** 비율이었다. 크기 통계만으로는
> 두 해석을 구분할 수 없었고, Phase 1(육안 검증)을 취소한 것이 그래서 잘못이었다.
>
> **결과적으로 `hook_unfastened` 라는 클래스명은 실제 라벨과 맞지 않는다.**
> 현재 hook 모델이 학습한 것은 같은 사람에 대한 **중첩된 두 박스(몸통 / 전신)** 이며
> 사실상 중복 클래스다. 타겟을 "미체결 작업자 상태 탐지"로 재정의하든,
> 고리 영역을 직접 라벨하든 결정이 필요하다. 그 전까지 hook 모델은 baseline 이다.

`UA-01`과 `WO-06`은 개수만 비슷할 뿐 IoU>0.5 매칭이 3.2%인 **별개 어노테이션**이다.
단 그 "별개"는 부품과 사람이 아니라 **몸통과 전신**의 차이였다.

**YOLO 로 고리를 탐지하지 않는다.** 원본 1920×1080 에서 고리(카라비너)를 눈금자로
재보니 **약 18~25 px** 이다. imgsz 640 으로 줄이면 6~8 px 라 탐지가 성립하지 않는다.

박스 크기 중앙값은 몸통(`WO-06`) 109×286 px, 전신(`UA-01`) 168×491 px 다.
긴 변을 640 으로 맞춰 잘랐을 때 고리가 몇 px 가 되는지 계산하면 이렇다.

| 방식 | 배율 | 고리 크기 | 판단 |
|---|---:|---:|---|
| 전체 프레임 640 | 0.33x | 6~8 px | 불가능 |
| 전체 프레임 1280 | 0.67x | 12~17 px | 매우 어려움 |
| 전체 프레임 1920 | 1.0x | 18~25 px | 가능하나 학습 비용 급증 |
| **전신 크롭 → 640** | **1.30x** | **23~33 px** | **채택** |
| 몸통 크롭 → 640 | 2.24x | 40~56 px | 고리는 가장 크나 앵커가 잘릴 수 있다 |

> 크롭의 배율은 **VLM 입력 해상도**에 달렸지 YOLO 의 640 과는 무관하다. 전신 크롭을
> 896 으로 넣으면 고리는 33~46 px 가 된다. 고리가 더 커야 하면 몸통 쪽으로 좁히면
> 되지만, 그만큼 앵커(난간·구명줄)가 화면에서 잘려 체결 판정 근거가 사라진다.
> 이 균형은 VLM 을 실제로 붙여 본 뒤 조정할 것.

그래서 **1단계 YOLO 는 작업자를 찾고, 체결 여부는 2단계 VLM 이 판단한다**
(README 5절의 계층 구조 그대로다).

전신(`UA-01`)을 쓰고 몸통(`WO-06`)은 쓰지 않는다. 둘은 같은 사람의 중첩 박스라
두 클래스로 배울 이유가 없고, 실측에서 전신이 사람과 97.7% 겹쳐 몸통(80.3%)보다
정확했다 ([`train_results.md`](train_results.md) 4.1절). 체결 여부를 보려면 고리가
걸릴 앵커(난간·구명줄)까지 보여야 하므로 크롭에 여유가 있는 편이 낫다.

> **클래스명에 상태를 넣지 않는다.** 507 에는 체결 상태 라벨이 없어 상태를 배울 수
> 없다. 박스는 "미체결 작업자" 가 아니라 그냥 "작업자" 이고, 미체결 여부는 VLM 이
> 판단한다. 이전 이름 `hook_unfastened` / `worker_unfastened` 는 라벨이 담지 않은
> 정보를 주장하고 있었다.

> **홀드아웃 없이 전량 학습한다.** 위 인스턴스 수는 클립 단위 분할을 전제한
> 옛 값이었다. 현장 단위로 올려 실측하니 `WO-06` 이 라벨된 4,041 프레임이 **전부
> 현장 A03 한 곳**이다. 촬영일 3일(210821 280 / 210823 578 / 210826 3,183),
> 클립 15개인데 그중 12개가 210826 하루를 여러 카메라로 찍은 것이다.
> 현장 단위 분할이 성립하지 않고, 클립 단위로 나누면 6절에서 막으려는 누수가
> 그대로 재현된다. 내부 지표를 만들지 않고 외부 검증셋으로 평가한다 (8절).

정의는 `configs/data/targets.yaml`, 변환은 `scripts/build_dataset.py`.

## 6. 절대 규칙 (README 8절)

- **프레임 단위 랜덤 분할 금지.** 반드시 영상 ID 단위로 분할한다.
  - 507 영상 ID: `H-210717_E01_E_WS-20_201` (파일명 끝 프레임 번호 제외)
  - 71407 영상 ID: `H-220609_G18_SO-42_001`
- 비율 train 70 / val 15 / test 15, 상황유형·촬영기기 층화
- 분할 스크립트와 seed를 커밋 (`src/data/split.py`, `results/*/fold*.split.json`)
  - **`data/yolo/*/split.json` 을 커밋하라는 예전 규칙은 실행이 불가능했다.**
    `.gitignore` 의 `/data/` 에 걸리고, 실제 데이터셋은 저장소 밖 `D:/yolo/` 에 있다.
    `scripts/collect_results.py` 로 추적되는 `results/` 에 복사한다:

    ```bash
    python scripts/collect_results.py D:/yolo/guardrail
    ```

    이미지는 옮기지 않는다. 재현에 필요한 것은 현장별 split 배정과 지표뿐이다.

> **seed 3회 반복 시 학습 seed만 바꾸면 안 된다.** 분할 seed도 함께 바꿔야
> 영상 배정의 분산이 지표에 반영된다. 영상이 15~36개뿐이라 이 분산이 크다.
>
> **단, guardrail 에는 이 규칙이 적용되지 않는다.** 현장이 A04/A08/A17/A21
> 네 곳이고 k=4 라 각 폴드가 정확히 현장 하나를 받는다. `carve_val` 은 seed 를
> 받지도 않는다. 그래서 분할 seed 는 **폴드 번호만 뒤섞고 실험 집합은 그대로**다
> (seed 0/1/2 로 배정을 생성해 동일함을 확인). 반복 가능한 것은 학습 seed 뿐이다.
> 자세한 건 `train_results.md` 1.1절.

> `--copy` 는 선택이 아니다. D 드라이브는 심볼릭 링크를 지원하지 않아 기본 동작이

> 스크립트가 찍는 em dash 에서 `UnicodeEncodeError` 가 난다. `train_kfold.py` 는
> 그 지점이 **4폴드를 다 학습한 뒤 집계를 저장하기 직전**이다.

### k-fold 설계

`k=4` 기준 각 폴드에서 **test = fold i 현장, 나머지 현장이 train**이고
val 은 train 현장의 세션에서 뗀다 (`split.carve_val`). test 를 val 로 겸용하면
조기종료가 test 를 보게 되어 지표가 낙관적으로 샌다.

`k=2`는 train 이 비므로 **k는 3 이상**이어야 한다. 코드가 막아 둔다.
`SO-01` 이 라벨된 현장이 A04/A08/A17/A21 네 곳이라 `k=4` 가 곧
leave-one-site-out 이다. val 까지 현장 단위로 빼면 train 이 2현장으로 줄어들어
그렇게 하지 않는다 (6절).

`train_kfold.py`는 폴드별 mAP50, mAP50-95, precision, recall 과
**클래스별 AP@0.5**(README 9절 필수 보고 항목)를 mean ± std 로 집계해
`kfold_metrics.json`에 저장한다.
