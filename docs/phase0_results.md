## 2. README 13절 "WO와 UA는 동일 인스턴스다"는 사실과 다르다

`WO-06`(안전고리 미착용)과 `UA-01`(안전고리 미체결)의 관계를 실측했다.

| 항목 | 값 |
|---|---|
| 두 코드가 함께 등장하는 프레임 | 36,452 |
| IoU > 0.5 로 매칭되는 박스 | 1,151 / 36,454 = **3.2%** |
| `UA-01` 면적 중앙값 | 0.0323 (`WO-01` 작업자의 **0.76배**) |
| `WO-06` 면적 중앙값 | 0.0114 (`WO-01`의 **0.27배**) |

개수만 40,496 대 40,499로 비슷할 뿐, **서로 다른 대상을 라벨링한 별개의 어노테이션**이다.

- `UA-01` — 작업자 전신에 가까운 크기. 사람 단위 **상태** 라벨
- `WO-06` — 그보다 훨씬 작음. 고리·부착부 **부품** 라벨
  → **폐기.** 실제로는 작업자 **몸통**이다 (상단 배너)

> README 13절의 "데이터가 두 배라고 착각하지 말 것"은 근거가 성립하지 않는다.
> 실제로는 성격이 다른 두 라벨이 모두 존재하며, 둘 다 쓸 수 있다.
> 안전모(`WO-04` 0.0020 vs `UA-04` 0.0386)도 20배 차이로 같은 패턴이다.

### 결론: A안 채택 — **폐기됨**

`docs/data_plan.md` 2절에서 제기한 "안전고리에 positive 클래스가 없다" 리스크는 해소됐다.
`WO-06`을 부품 클래스로 학습하고, `UA-01`은 사람 단위 판정의 보조 라벨로 쓴다.

> **이 결론은 성립하지 않는다.** `WO-06` 이 몸통이므로 두 라벨은 같은 사람의 중첩
> 박스이고, "positive 클래스가 없다" 는 리스크는 **해소된 적이 없다.** 507 에는
> 체결 상태 라벨이 없어 체결/미체결을 구분하는 모델을 만들 수 없다.

`WO-05` 안전벨트 미착용(0.0064 → 640에서 37×37)이다. 9종으로 확장할 때 재검토할 것.

## 6-2. 영상 다양성이 이 데이터셋의 진짜 한계다

타겟이 실제로 라벨된 영상 수를 Training / Validation 파티션별로 세어 봤다.

| 타겟 | 조건 | label_train | label_val |
|---|---|---|---|
| 안전난간 `SO-01` | 비계작업 · WS | 영상 **36** / 프레임 15,418 / 52,150건 | 영상 **36** / 프레임 1,912 / 6,464건 |
| 안전고리 `WO-06` | 공통 · UA | 영상 **15** / 프레임 32,411 / 32,413건 | 영상 **15** / 프레임 4,041 / 4,041건 |

### AI Hub 의 train/val 분할은 영상 단위가 아니다

두 파티션의 **영상 집합이 완전히 동일하다.** 같은 영상에서 프레임만 나눠 담았다.
즉 AI Hub 제공 분할을 그대로 쓰면 train 과 val 에 인접 프레임이 섞여
**성능이 크게 부풀려진다.** README 8절이 경고하는 바로 그 상황이다.

> 이 데이터셋으로 보고된 성능 수치를 인용할 때는 분할 방식을 확인해야 한다.
> 발표에서 짚을 만한 지점이다.

### 결론: Training 원천을 받을 이유가 없다

`TS_05_비계작업` 185 GB, `TS_03_공통` 122 GB 를 받아도 **같은 36개 / 15개 영상에서
프레임이 8배 늘어날 뿐 새로운 장면은 하나도 없다.** 인접 프레임은 거의 동일하므로
유효 데이터 증가량은 미미하다. **307 GB 를 받지 않는다.**

Validation 원천 38 GB 가 최선의 선택임이 확정됐다.

### 대신 감수해야 하는 것

영상 단위 분할 시 남는 영상 수가 적다.

| 타겟 | 영상 | 70/15/15 분할 결과 |
|---|---|---|
| 안전난간 | 36 (+배경 89) | train 87 / val 19 / test 19 영상 |
| 안전고리 | **15** | **train 11 / val 2 / test 2 영상** |

안전고리의 test 가 사실상 장면 2개다. 단일 분할의 지표는 분산이 매우 크다.

권장:
1. 안전고리는 단일 분할 대신 **영상 단위 group k-fold** 로 평가한다 (k=5, 영상 3개씩)
2. README 6절의 외부 검증셋(SODA 등) 평가가 선택이 아니라 **필수**가 된다.
   15개 영상에서 학습한 모델의 일반화를 내부 지표로 주장할 수 없다
3. seed 3회 반복(README 8절)에 **분할 seed 변경도 포함**한다. 학습 seed만 바꾸면
   영상 배정이 고정되어 진짜 분산이 드러나지 않는다

## 7. 다음 단계에 반영할 리스크

### 두 타겟이 서로 다른 작업유형에 배타적으로 존재한다

안전난간은 비계작업 이미지에만, 안전고리는 공통 이미지에만 라벨이 있다.
**두 파티션을 합쳐 단일 모델로 학습하면 서로의 클래스에 대해 라벨 없는 positive가 생긴다.**
공통 이미지에 안전난간이 찍혀 있어도 라벨이 없으므로 모델은 그것을 배경으로 학습한다.

권장: **안전난간 모델과 안전고리 모델을 분리 학습한다.**
합칠 경우 클래스별 loss 마스킹이 필요하며 Ultralytics 기본 학습 루프로는 지원되지 않는다.

- `UC-01` / `UC-04` 의 실제 차이 (원천 이미지 육안 확인)
- `WO-06` 박스가 고리 자체인지 부착부 전체인지 (원천 이미지 육안 확인)
