# 평가 프로토콜 — 무엇을 어떻게 재고, 무엇을 주장할 수 있는가

`README.md` 9절의 합격 기준을 실제로 실행 가능한 형태로 고정한다.
실측치는 [`train_results.md`](train_results.md), 현재 상태는 `HANDOFF.md`(로컬 전용).

**이 문서를 쓰는 이유.** 1단계 탐지가 원래 기준에 미달했고, 그 원인을 분석하다
평가 단위 자체가 제품 질문과 어긋나 있음을 확인했다. 기준을 바꾸는 것은 정당하지만
**바꾸면서 원래 기준의 미달을 지우면 그것이 지표 세탁이다.** 그래서 두 기준을
나란히 둔다.

> **2026-08-25 제품 전환 반영.** 실시간 경보를 버리고 **사진 업로드 → 위반 리포트**
> 로 간다 (`README.md` 4·5절). 이 문서에 미친 영향은 세 가지다.
>
> 1. **단위가 "구역" 에서 "지점" 으로 바뀐다.** 실체는 같다 — 판정 대상 한 칸이다.
>    아래 본문의 "구역" 은 그대로 읽어도 된다.
> 2. **이벤트 단위(3.6)는 보류한다.** 1단계는 사진만 받으므로 트래킹이 없다.
>    영상 입력을 열 때 되살린다. **삭제하지 않는다.**
> 3. **채점 대상이 이진에서 요소 단위로 넓어진다** (3.7 신설). 단 **4요소 원안은
>    실측으로 깨졌다** — 판별 요소는 둘뿐이다. 그리고 **판정 불가를
>    무엇으로 셀지 고정하는 것이 필수 절차가 된다** (3.8 신설).
>
> **알람 지연 지표는 폐기됐다.** 대신 사진 1장당 처리 시간을 기술통계로만 낸다.

## 2. 기준 A — 결과와 대조

`README.md` 9절 의 "1단계 탐지 mAP@0.5 최소 0.70 / 목표 0.85".

| 값 | 실측 | 대조 |
|---|---:|---|
| **3클래스 site-macro mAP@0.5** | **0.559** | **형식적 대조값. 0.70 미달** |
| 핵심 클래스 `guardrail` AP@0.5 | 0.365 | 함께 보고. `worker` 0.889 가 평균을 끌어올림 |
| 외부(71407) mAP@0.5 | 0.02 | 사실상 동작하지 않음 |
| 프레임 가중 평균 | 0.523 | **대조값으로 쓰지 않는다** (아래) |

**대조는 `0.559` 로 한다.** `README.md` 9절 이 mAP 와 클래스별 AP 를 별개로
요구하므로 형식적 기준값은 클래스 전체 매크로다. `0.365` 만 들어 "미달" 이라
하면 가혹하고, `0.559` 만 보고하면 핵심 클래스의 붕괴를 감춘다. **둘을 병기한다.
어느 쪽으로 읽어도 합격이 아니다.**

프레임 가중 평균을 쓰지 않는 이유: AP 는 비선형이라 폴드별 AP 를 프레임 수로
가중해도 pooled AP 가 아니고, A04 를 954프레임 찍었다는 사실이 배포 환경의
빈도를 뜻하지도 않는다 (`train_results.md` 1.1절).

> **기준 A 자체의 결함도 기록한다.** README 기준은 클래스 집합과 보조 클래스
> 취급을 정하지 않았다. `worker` 같은 보조 클래스를 넣고 빼면 합격 여부가 바뀐다.
> 앞으로는 **안전 대상 클래스 매크로**와 **보조 클래스**를 분리해 보고한다.

## 3. 기준 B — 구역 단위 판정

### 3.1 구역(ROI)이 어디서 오는가 — 먼저 정해야 한다

현재 `scripts/zone_eval.py` 는 **정답 박스를 그대로 ROI 로 쓴다(oracle ROI).**
배포에는 그 구역을 만들어 줄 것이 없고, `README.md` 5절 아키텍처에도 구역 생성
단계가 없다. 따라서 지금 수치는 **"판정할 구역이 주어졌을 때"** 의 값이다.

둘 중 하나를 골라야 한다.

| 안 | 내용 | 대가 |
|---|---|---|
| **B-1 지정 ROI** | 점검자가 구역을 지정하거나 고정 카메라에 ROI 를 등록 | 제품 정의에 전제를 명시해야 함. 자동 감시가 아님 |
| B-2 자동 | 구역 제안기를 포함해 엔드투엔드 평가 | 제안기를 만들어야 하고, 그 성능이 상한이 됨 |

**B-1 로 확정한다 (2026-08-25).** 사진 업로드 제품에서도 **ROI 문제는 해소되지
않는다** — 사진은 **장면**을 지정할 뿐 "난간이 있어야 하는데 없는 지점" 을
지정하지 않는다. 따라서 **사용자가 화면에서 지점을 찍는 UI** 를 전제로 한다.
자동 감시가 아님을 제품 정의에 명시한다.

> **제안기를 만든다면 난간이 아니라 단부·개구부·작업발판을 찾아야 한다.**
> 찾아야 하는 것은 난간이 **없는** 곳이므로 난간 탐지기는 그 위치를 제안할 수
> 없다. B-2 를 재검토할 때 이 점부터 볼 것.

**주의 — 지정 ROI 는 면적비를 흔든다.** 현재 면적비는 **정답 박스에서** 계산된다.
사람이 ROI 를 크게/작게 그리면 면적대와 `cov` 판정이 동시에 흔들린다. 크기 창을
제품 제약으로 쓰려면 **ROI 작성 규칙의 재현성이 전제**다.

"고정 카메라 정상 기준 이미지와 비교" 방식은
507 로 검증할 수 없다 — 507 은 1인칭(device 0)·3인칭(device 1) **이동 촬영**이다
(`scripts/build_dataset.py` 의 `session_id` 주석).

### 3.2 판정 규칙 (test 를 더 보기 전에 고정)

```
구역에 대해: 구역 면적의 cov 이상을 덮는 guardrail 예측이 하나라도 있으면
             "난간 있음", 없으면 "난간 없음" = 알람
기본값:      cov = 0.3, 단일 박스 기준, IoU 아님
```

IoU 를 쓰지 않는 이유: 미설치 구역은 난간이 없어 칸 전체를 잡으므로 정상 구역보다
크다. IoU 는 그 크기 차이 때문에 두 구역을 다른 잣대로 재게 된다.

**이 규칙이 결과를 만들어내지 않음을 확인했다** (`train_results.md` 1.6절):
cov 를 0.1~0.5 로 바꿔도 J 가 안정적이고(A17 0.418~0.455), 단일 박스와 합집합의
차이는 |ΔJ| < 0.05 다. **따라서 cov=0.3, 단일 박스로 고정한다.**

### 3.3 지표

| 지표 | 분모 | 역할 |
|---|---|---|
| **미설치 적발률** = TPR (민감도) | 실제 위반인 지점 | **공동 주지표.** 놓치면 사고다 |
| **오경보율** = **FPR** (1 − 정상구역 검출률) | 실제 정상인 지점 | **공동 주지표.** 높으면 점검자가 무시한다 |
| **FDR**(p) — 잘못된 알람 / 전체 알람 | **시스템이 알람 낸 지점** | **조건부 병기.** 주기준이 아니다 (3.4) |
| J = 적발률 + 정상검출률 − 1 | — | 요약값. 단독 합격 지표로 쓰지 않는다 |
| 정밀도 · F1 | — | **참고값.** 평가셋의 정상:미설치 비율에 의존한다 |

**분모를 지표 이름 옆에 적는 것이 이 표의 요점이다.** 오경보율의 근거 문장과
구현이 서로 다른 분모를 쓰고 있었고 아무도 못 봤다 (3.4, `train_results.md` 6절 16번).

**집계 단위는 site-macro-of-clip-macro 다.** 클립별 값을 낸 뒤 **현장 안에서
클립을 동일 가중**해 macro 를 내고, 그 현장값을 **다시 동일 가중**한다.
구역으로 나눈 값은 **기술통계로만** 병기한다.

> **2026-08-29 정정.** 이 절은 원래 "클립을 전부 동일 가중" 이라고 적었는데
> `ppe_baseline.py` 와 `zone_eval.py` 는 처음부터 현장을 한 번 더 묶고 있었다.
> **코드가 맞고 문서가 낡았다.** 클립 수가 현장마다 2~9 로 다르므로 전체 클립
> 동일 가중은 클립이 많은 현장에 가중을 준다. 그리고 주장하려는 것이
> "안 본 **현장**에서도 되는가" 이므로 최상위 군집은 현장이어야 한다.
> **신뢰구간도 클립이 아니라 현장 계층 bootstrap 을 주로 쓴다** (3.4).

집계 단위가 결론을 바꾼다 — A17 conf 0.005 의 적발률이 구역 가중 90.1% 대
클립 macro 72.5% 다 (`train_results.md` 1.7).

**사진 단위 지표를 함께 낸다 (신설 — 2026-08-29).** 위 지표는 전부 **지점**이
분모다. 그런데 제품이 내보내는 것은 **사진 한 장에 붙는 리포트**이므로 사용자가
겪는 실패 단위는 사진이다. 사진 한 장에 지점이 여럿이면 지점 지표가 좋아도
사진 단위로는 나빠질 수 있다.

| 지표 | 정의 |
|---|---|
| **헛경보 사진률** | 위반이 없는 사진에서 위반 줄이 **하나라도** 생성될 확률 |
| **사진당 틀린 줄 수** | 리포트 줄 중 오판정 개수의 사진 평균 |
| **전행 정답률** | 리포트의 **모든** 줄이 맞는 사진의 비율 |

**헛경보 사진률이 운용상 가장 아픈 값이다** — 점검자는 줄이 아니라 사진을 연다.
이 셋은 **작업자 전수 주석이 있어야 잴 수 있다.** 지금은 프레임당 정답이 1명뿐
이라 "나머지 작업자에게 난 알람" 이 어디에도 세어지지 않는다
(`train_results.md` 5.9).

**J 를 단독으로 쓰지 않는 이유:** J 는 미탐과 오경보의 비용을 같게 둔다.
`README.md` 9절 는 안전 도메인이므로 **recall 우선**을 요구한다.

**정밀도·F1 을 주지표로 쓰지 않는 이유:** 실측에서 A21 이 conf 0.25 에서
정상 구역을 **0%** 검출하면서 F1 0.846 을 냈다. 모든 구역에 알람을 울렸고
평가셋의 74% 가 미설치라 정밀도가 저절로 0.74 가 된 것이다. J 는 −0.006 으로
이를 잡아낸다. **실제 현장은 정상 구역이 훨씬 많으므로 배포 시 정밀도는 더 낮다.**

### 3.4 합격 기준

**제품 요구에서 도출한다. 관측값에서 역산하지 않는다.**

| 항목 | 지표 | 최소 | 목표 |
|---|---|---|---|
| 미설치·미착용 적발률 | **TPR** | **0.80** | 0.90 |
| 오경보율 | **FPR** | **0.20 이하** | 0.10 이하 |

#### 근거 문장을 지표별로 분리한다 (2026-08-29 정정)

적발률의 근거는 안전 도메인의 **recall 우선 원칙**(`README.md` 9절)이다.
이건 그대로다.

**오경보율은 근거와 구현이 어긋나 있었다.** 원래 근거 문장은 이것이다 —
"다섯 구역 중 하나가 헛경보면 점검자가 알람을 무시하기 시작한다."
이 문장은 **리포트에 뜬 줄 다섯 개 중 하나**를 말하므로 **FDR** 이다.
그런데 구현은 **알람이 난 정상구역 / 전체 정상구역**, 즉 **FPR** 이다.
둘은 유병률에 따라 갈라지고, 평가셋 유병률 43.6% 가 **`sample()` 이 pos/neg 를
클립당 균등 추출해서 나온 표집 산물**이라 우연히 비슷해 보였다
(`train_results.md` 5.9, 6절 16번).

**결정: FPR 을 주기준으로 유지한다.** FDR 로 갈아타면 안 된다 — FDR 은 유병률이
오르기만 해도 **같은 모델의 점수가 좋아진다.** 현장이 위험해질수록 점수가 오르는
값을 합격 기준의 본체에 둘 수 없다.

**대신 FDR(p) 를 조건부로 병기한다.** 원래 근거 문장이 FDR 이었으므로 그 문장을
만족하는지도 함께 보고해야 한다. 세 가지를 낸다.

1. 측정한 TPR·FPR 로 **유병률 p 를 넣은 곡선**을 낸다.
   `FDR(p) = (1−p)·FPR / [ (1−p)·FPR + p·TPR ]`
2. **손익분기 유병률** — "리포트의 80% 는 맞다"(FDR ≤ 0.20)를 만족하는 최소 p.
3. **p 는 추정하지 않는다.** 현장 실제 미착용률을 우리는 모른다. 곡선과 손익분기점
   만 내고 **"이 기준을 만족하려면 현장 미착용률이 얼마 이상이어야 한다"** 로 읽는다.

> **실측 예 (보호구).** 5.8 고정조합(TPR 82.0% / FPR 12.4%)의 손익분기 유병률은
> **37.7%**, cross-fitted LOSO(78.2% / 13.6%)는 **41.0%** 다. 작업자 열 명 중
> 넷이 안전모를 안 쓴 현장이어야 리포트의 80%가 맞는다는 뜻이다.
> **이 값은 site-macro TPR/FPR 에 단일 p 를 넣은 설명용 근사다** — 현장별
> 유병률과 오류율이 함께 움직이면 pooled FDR 과 다르다 (`train_results.md` 5.9).

#### 합격 / 실패 / 불충분 — 3상태로 판정한다 (신설 — 2026-08-29)

**점추정치만 보고 합격·미달을 단정하지 않는다** (`train_results.md` 6절 17번).
아래를 **측정 전에 고정한다.**

1. 두 주지표 각각에 **현장 계층 percentile bootstrap 95%** 를 붙인다.
   재표집 단위는 **현장**이다. 클립이 아니다 — 주장하려는 것이 "안 본 현장에서도
   되는가" 이므로 최상위 군집이 현장이다. `reps = 1000`, seed 고정.
2. **지표별로** 먼저 판정한다.

   | 조건 | 판정 |
   |---|---|
   | 구간 전체가 기준선의 **합격 쪽** | **합격** |
   | 구간 전체가 기준선의 **실패 쪽** | **실패** |
   | 구간이 **기준선을 물고 있다** | **불충분** |

3. **전체 판정** — 하나라도 실패면 **실패**, 아니면 하나라도 불충분이면
   **불충분**, 둘 다 합격일 때만 **합격**.
4. **불충분은 실패가 아니다.** "이 데이터로는 못 정한다" 이고, 대응은 모델 수정이
   아니라 **표본 확대**다. 이 구분을 안 두면 표본이 모자란 것을 모델 탓으로 돌리고
   엉뚱한 데를 고치게 된다.

구현은 `ppe_baseline.py` 의 `verdict()` 다.

> **현재 보호구 값이 정확히 이 경우다.** LOSO 적발 78.2% **[58.9%, 91.7%]** ·
> 오경보 12.4% **[5.5%, 20.6%]** 로 **두 구간이 전부 기준선을 문다.** 따라서
> 판정은 **불충분**이다. `train_results.md` 5.8 이 쓴 "적발 1.8%p 미달" 은
> 점추정만 본 서술이고 5.9 에서 정정했다.
>
> 군집이 7개뿐인 percentile bootstrap 은 그 자체로 신뢰도가 낮다.
> **"구간이 넓다" 는 사실만 읽을 것.** 좁게 나오면 그게 이상한 것이다.

#### 난간(기준 B) 현재 값

**현재 최선(A17 conf 0.005)은 클립 macro 로 적발 72.5% / 오경보 39.0%** 다.
구역 가중치로는 90.1% / 46.7% 였다 — 적발률이 기준을 넘는 것처럼 보였던 것은
집계 단위 탓이다 (`train_results.md` 1.7).

**면적대를 0.10~0.20 으로 제한하면 A17 한 현장이 클립 macro 로도 기준을 넘는다**
(적발 89.4% / 오경보 3.5%). 다만 4.4절에 따라 합격 선언에는 쓸 수 없고, 같은
임계가 A04·A21 에서는 기준을 넘지 못한다.

> **이 값들에는 아직 3상태 판정을 적용하지 않았다.** 난간은 평가 가능한 현장이
> 3곳뿐이라(4.1) 현장 계층 bootstrap 이 사실상 의미를 갖지 못한다.
> **재측정할 때 함께 붙인다.** 그때까지 위 수치는 점추정으로만 읽는다.

### 3.5 임계 선택 절차

1. `conf` 와 `cov` 는 **개발 데이터에서** 정하고 모든 test 현장에 **동일하게** 적용한다.
2. **test 현장에서 고르지 않는다.** `train_results.md` 1.6절의 J 0.29~0.43 은
   현장마다 conf 를 test 에서 고른 **oracle Jmax** 이며 배포 성능이 아니다.
3. train 현장에서 뗀 val 로 고르는 것도 위험하다 — 1.3절에서 그 방식이 일반화되지
   않는 클래스에서 실패함을 확인했다. 임계 선택용 현장을 따로 떼는 것이 원칙이다.

### 3.6 이벤트 단위 (미구현 — **보류**)

`README.md` 가 요구했다 — 트래킹 스무딩 후 **이벤트 단위 precision/recall**,
구역·시간당 오경보, 최초 탐지 지연. **아직 구현하지 않았다.**

> **2026-08-25: 보류한다. 삭제하지 않는다.** 1단계는 사진만 받으므로 트래킹이
> 없다. **영상 입력을 여는 조건이 곧 이 절의 구현**이다 — 영상은 같은 위반이
> 프레임마다 중복 보고되고, 그것을 재는 지표가 여기 있다.
> 단 **"최초 탐지 지연" 은 되살리지 않는다.** 실시간 경보를 버렸다.

### 3.7 요소 단위 채점 (신설 — **판별 2요소만. 정답은 아직 없다**)

리포트가 조항을 걸려면 **어느 부품이 빠졌는지** 말해야 한다 (`README.md` 4절).
원안은 법령 4요소 `상부 난간대 / 중간 난간대 / 발끝막이판 / 난간기둥` ×
`확인됨 / 미확인 / 가려짐` 이었다. **2026-08-25 크롭 육안 확인이 이를 깼다**
(`train_results.md` 1.9, 53장/36클립/4현장).

| 요소 | 정상(`SO-01`) | 미설치(`UC-01`) | 판별력 |
|---|---|---|---|
| 상부 난간대 | 있음 | 없음 | **있다** |
| 중간 난간대 | 있음 | 없음 | **있다** |
| 난간기둥 | 있음 | **있음** | 없다 |
| 발끝막이판 | **없음** | 없음 | 없다 |

**발끝막이판은 해상도 문제가 아니라 물리적 미설치**다 — A08 은 구역 폭
1,065~1,082px 인데도 발판 가장자리가 맨 철판이다. 따라서 **제13조를 엄격히
적용하면 `SO-01` 구역도 전부 위반**이고, **"`SO-01` = 적법" 전제가 깨진다.**

> **상수 요소를 채점에 넣으면 지표가 자동으로 부푼다.** 4요소 전부를 채점하면
> 둘은 항상 맞으므로 요소별 평균 정확도가 근거 없이 올라간다. 이 문서 3.3 이
> 요구하는 **퇴화 해 확인**이 바로 이런 경우를 잡기 위한 것이다.

**결정 (2026-08-25): 판별 2요소(상부 난간대·중간 난간대)만 채점한다.**
난간기둥·발끝막이판은 **관측 결과로 표시하되 채점하지 않는다.**
`README.md` 9절에 3안 비교와 대가를 적었다.

**스키마와 무관하게 지키는 것.**

| 무엇을 내는가 | 규칙 |
|---|---|
| 요소별 정확도 | 채점 대상 요소 각각. **상수 요소를 넣었다면 반드시 분리 표기** |
| **전 요소 동시 정답률** | 조항 연결에 실제로 쓰이는 값 |
| **대체 방호조치 정확도** | 울타리·수직형 추락방망·덮개. 없으면 제43조 판정이 성립하지 않는다 |
| **면적 metadata baseline** | 크롭 면적·종횡비만 쓰는 분류기. **반드시 병기한다** |
| **퇴화 해** | "전부 확인됨" 이 몇 점인지 |

**metadata baseline 을 왜 강제하는가.** `SO-01` 면적비 중앙값 0.0579 대 `UC-01`
0.1111 로 **2배 차이**가 난다 (`train_results.md` 1.5). 이것을 재 두지 않으면
VLM 이 **난간 구조를 본 것인지 크롭 크기를 본 것인지 구분할 수 없다.**

**정답이 없다.** 507 은 이진 라벨뿐이다. 200~300장 2인 독립 라벨링 + kappa 0.60
이 선행 조건이고, 표집에는 **A21 을 반드시 넣는다** — A17·A04 의 미설치는 명백한
반면 A21 은 프레임 가로재 때문에 경계 판정이다. 쉬운 현장만으로 재면 **kappa 가
부풀려진다** (`train_results.md` 1.9).

**판정 단위에 면적 하한을 건다.** A17 `UC-01` 의 최소 면적대는 100×415px 같은
**세로 슬리버**로 "비계 한 칸" 이 아니다. 판정 불가능한 대상을 분모에 넣으면
성능을 잘못 재게 된다. 현재 0.10 은 측정값이 아니라 `bands` 하드코딩 경계이므로
**근거를 만들어 다시 정한다.**

### 3.8 판정 불가 처리 (신설 — **모델을 돌리기 전에 고정한다**)

`가려짐` · 화질 부족 · 각도를 **오경보 / 미탐 / 수동 검토** 중 무엇으로 셀지
**결과를 보기 전에** 정한다. 그러지 않으면 결과에 규칙을 맞추게 된다.

> **2026-08-25 파일럿 결과 — 이 절은 아직 구현할 수 없다.** Qwen2.5-VL 7B 가
> 상부 난간대에 대해 **`판정불가` 를 0건** 냈다 (272구역 중 0). 프롬프트가
> "확신할 수 없으면 판정불가" 를 명시했는데도 쓰지 않는다. 그래서 아래 세 규칙이
> 전부 같은 값을 낸다. **기권 예산은 별도 신뢰도 점수(로짓·자기일관성)가 있어야
> 성립한다** (`train_results.md` 1.10).

**권장안**: 수동 검토 큐로 분리하되 **기권 예산을 사전 고정**한다.

그러려면 세 가지가 함께 정해져야 한다.

1. **기권 판단 점수** — 무엇을 근거로 "판정 불가" 라 하는가
2. **그 임계** — 기권 예산을 어디서 끊는가 (아래에서 고정한다)
3. **임계를 정할 calibration 집합** — 아래 3.5 와 같은 문제에 부딪힌다

#### 기권 예산 — 총량이 아니라 두 값으로 건다 (신설 — 2026-08-29)

**기권에 예산이 없으면 전부 기권하는 모델이 오경보 0% 를 받는다.**
`판정불가`·`사람미탐` 은 positive 에서 적발을 깎지만 **negative 에서는 오경보를
낮춰 준다.** 운용점 스윕의 선택 규칙에 기권 제약이 없어서 보상이 한쪽으로만
기울어 있었다 (`train_results.md` 5.9).

| 예산 | 상한 | 왜 이걸로 재나 |
|---|---|---|
| **음성 기권율** — 실제 정상 지점 중 기권 비율 | **잠정 0.10** | 오경보를 부당하게 낮춰 주는 것은 **음성 쪽 기권**뿐이다 |
| **사진 100장당 수동 검토 건수** | **잠정 20건** | 사람이 실제로 감당하는 양. 운용 비용의 단위다 |

> **두 상한값 자체는 아직 제품 요구에서 도출하지 않았다.** 3.4 가 "관측값에서
> 역산하지 않는다" 고 요구하므로, 위 숫자는 **구조만 확정하고 값은 잠정**이다.
> 점검자가 하루에 처리하는 사진 수를 확인해 확정할 것. **확정 전까지는 이
> 예산을 건 수치를 합격 판정에 쓰지 않는다.**

**양성 기권은 따로 제한하지 않는다.** 전수 기준 적발률이 이미 `판정불가` 를
분모에 남기므로 손실로 잡혀 있고, 여기서 또 제한하면 **이중 계상**이다.

**총량 하나로 묶지 않는 이유가 그것이다** — 양성·음성 기권은 지표에 반대
방향으로 작용하므로 합치면 서로를 상쇄해 아무것도 통제하지 못한다.

**기권의 정의는 코드가 기준이다.** 머리 영역에 쓸 만한 PPE 박스가 하나도 없어
`판정불가` 가 난 경우, 그리고 작업자를 못 찾은 `사람미탐`. **helmet 과 no_helmet
이 함께 잡힌 충돌은 기권이 아니라 `착용`** 이다 (`ppe_baseline.py` 의
`classify()`). 예전 docstring 이 이 경로를 `판정불가` 라고 잘못 적어 두어
기권율을 셀 수 없는 상태였고, 2026-08-29 에 정정했다.

**이 두 예산은 운용점 선택에서 오경보 상한과 같은 지위의 제약이다** —
넘는 조합은 후보에서 뺀다.

> **calibration 집합은 여전히 미결이다.** 3.5 는 "임계 선택용 현장을 따로 뗀다"
> 인데 기준 B 는 현장이 **3곳뿐**이다(A08 은 `UC-01` 0건이라 빠진다). 하나를 떼면
> 평가가 2곳으로 준다. **현장을 뗄지 · 클립을 뗄지 · 원칙을 완화하고 명시할지**
> 를 정해야 한다. 정하기 전까지 기권 예산을 붙인 수치를 합격 판정에 쓰지 않는다.

**리포트에서는 판정 불가를 위반으로 계상하지 않는다.** 신뢰도 칸에 사유를 적고
수동 검토로 보낸다 (`README.md` 4절).

### 3.9 조항 연결 — **실재 검증은 적용 타당성을 보증하지 않는다** (신설)

`rag` 브랜치 파이프라인을 실제로 붙여 확인했다 (`train_results.md` 5.1).
안전모 미착용 쿼리에 **규칙 제32조(맞음)** 와 **제572조(방열복·방한복, 틀림)** 가
top-2 로 함께 왔고, **둘 다 `[API 검증 완료]` 로 찍혔다.** 제목이
"보호구의 지급 등" 으로 같아서 딸려 온 것이고, 조항이 실재하므로 검증을 통과한다.

- **환각률(실재)만으로는 이 실패를 못 잡는다.** `README.md` 9절에 **오적용률**을
  신설했다 — 실재하지만 적용되지 않는 조항을 인용한 비율.
- **채점에는 사람 정답이 필요하다.** 어느 조항이 적용되는지는 자동 판정이 안 된다.
  조·항·호 정규식 채점(LLM-as-judge 회피)의 장점이 여기서는 안 통한다.
- **리포트에 "검증 완료" 를 쓸 때 무엇이 검증됐는지 명시할 것.** 사용자는 그 표시를
  신뢰하는데 검증된 것은 **존재**뿐이다.

## 4. 표본과 주장 범위

### 4.1 독립 표본은 구역 수가 아니라 클립 수다

| 현장 | 정상구역 / 클립 | 미설치구역 / 클립 | 쓸 수 있나 |
|---|---|---|---|
| A17 | 1,290 / 7 | 1,051 / 9 | **O** |
| A04 | 4,306 / 20 | 125 / **2** | 미설치 쪽 불가 |
| A21 | 192 / **2** | 539 / 6 | 정상 쪽 불가 |
| **A08** | 430 / 1 | **0 / 0** | **평가 자체 불가** |

인접 프레임은 거의 동일하다. **구역 수를 표본 수로 읽지 않는다.**
집계는 클립/세션 블록 단위로 하거나 이벤트 단위로 올려야 한다.

> **기준 B 는 4현장이 아니라 3현장 프로토콜이다.** `A08` 은 `UC-01` 이 0건이라
> `zone_eval.py` 가 건너뛴다 — negative 가 없으면 적발률이 정의되지 않는다.
> **"k=4 에서 적발률·오경보율을 비교했다" 고 쓰면 안 된다.**
>
> 하필 A08 의 난간 면적비가 0.1811 로 네 현장 중 가장 크다
> (`train_results.md` 122·128행 — "한두 칸이 화면을 채운다").
> **5절 크기 가설이 작동한다는 면적대에 자연히 놓인 유일한 현장이 측정 불가**다.
> 가설에 가장 유리했을 증거를 못 쓰고 있다는 뜻이자, 크기 창 제품의 검증 대상이
> 3현장뿐이라는 뜻이다.

#### 최소 지지량은 지표별로 건다 (신설 — 2026-08-29)

**적발률과 오경보율은 서로 다른 자료를 쓴다.** 적발률에는 위반 클립이,
오경보율에는 정상 클립이 있어야 한다. 그런데 지금까지는 **양쪽을 다 가진
현장(paired)만** 평가에 넣었다 — `ppe_baseline.py` 가
`picks[s]["pos"] and picks[s]["neg"]` 로 현장을 걸렀다.

**규칙: 지표마다 그 지표에 필요한 클립이 2개 이상인 현장을 쓴다.**

| 지표 | 조건 | 현장 | 독립표본(클립) |
|---|---|---:|---:|
| **적발률** | 미착용 클립 ≥ 2 | **9** (A03·A15·A17·B02·C06·C15·D19·E07·E19) | **39** |
| **오경보율** | 착용 클립 ≥ 2 | **7** (A03·A04·A10·A15·B02·C06·E01) | **42** |
| 참고 — 현행 paired | 양쪽 ≥ 2 | 4 (A03·A15·B02·C06) | 23 / 33 |

**paired 요구가 적발 증거의 40% 를 버린다.** 그 대가로 사는 것은 현장별 J 하나
인데, J 는 3.3 이 이미 "단독 합격 지표로 쓰지 않는다" 고 못박은 값이다.

원인은 **507 에 착용 positive 라벨이 없어 `UA-02`/`UA-03` 상황으로 대체**한
것이다 — 평가 현장이 두 상황의 **교집합**으로 줄어든다. 그래서 미착용만 있는
A17·C15·E19(513구역/8클립)와 착용만 있는 A10·D12·E01(995구역/5클립)이 통째로
버려진다. **데이터가 없는 게 아니라 짝이 안 맞는다.**

**그래도 paired 4현장 민감도 분석은 필수로 남긴다. 없애지 않는다.**
현장 **내부**의 적발·오경보 **동시 실패**는 paired 에서만 보이기 때문이다 —
C06 이 적발 94.4% 인데 오경보 33.3% 인 것이 그 예다. 지표별 집합으로만 보면
이 현장이 두 표에 따로 들어가 서로를 가린다.

> **서로 다른 현장 집합의 두 수치를 묶어 "동시 합격" 이라고 쓰면 안 된다.**
> 적발 9현장 값과 오경보 7현장 값은 **같은 모집단의 값이 아니다.**
> 동시 만족 주장은 **paired 집합에서만** 하고, 지표별 값은 각각 따로 보고한다.
> (Codex 2차 의견, `train_results.md` 5.9)

### 4.2 지금 주장할 수 있는 것

- 507 leave-one-site-out 에서 **기준 A 를 충족하지 못했다.**
- **구역이 주어지는 조건에서** 세 현장 모두 관측 J > 0 이었다 (클립 macro).
- 그 적발률은 오경보율 39~66% 와 교환된 결과이며 **실용 운용점은 확보하지 못했다.**
- **같은 클립 안에서 구역이 클수록 정상 난간을 더 잘 찾는다** — A17 +91.7%p
  (공통 3클립), A04 +21.0%p (공통 3클립) 및 +8.3%p (공통 8클립). 촬영 조건을
  상수로 둔 paired 비교다 (`train_results.md` 1.7).
- 그 크기 효과는 **정상 구역 쪽에서만** 나온다. 미설치 구역 검출률은 면적대와
  무관하게 평평하다. 따라서 이것은 회수율 문제의 재서술에 가깝다.

### 4.3 주장할 수 없는 것

- 일반 건설현장에서의 기대 성능
- 안 본 현장에서의 성능 보장
- 엔드투엔드 미설치 탐지 (구역 제안기가 없다)
- 통계적으로 무작위보다 우수함 (클립 n 이 2~9)
- 현재 임계가 배포 가능한 값이라는 것

### 4.4 현재 test 는 합격 판정에 재사용하지 않는다

A04/A08/A17/A21 네 현장은 ablation, 임계 진단, 해상도 판단, 구역 규칙 설계에
**반복 사용했다.** 이제 test 가 아니라 **development CV** 다.
71407 도 마찬가지다 (`train_results.md` 2절).

**합격 선언에는 의사결정에 전혀 쓰지 않은 새 현장이 필요하다.**
현재 수치는 전부 **"프로토콜 설계를 위한 탐색 결과"** 로 남긴다.

### 4.5 잠금 확인셋 — 이름부터 "holdout" 이 아니다 (신설 — 2026-08-29)

4.4 가 요구하는 "의사결정에 전혀 쓰지 않은 현장" 을 보호구 트랙에서 세어 보면
**넷뿐이다.**

| 현장 | 쪽 | 잴 수 있는 지표 |
|---|---|---|
| **C15 · E19** | 미착용 | 적발률만 |
| **A10 · E01** | 착용 | 오경보율만 |

**A17 은 난간 트랙에서 이미 썼다.** 그래서 후보에 없다.

**이것을 "최종 holdout" 이라 부르지 않는다.** 이유가 셋이다.

1. **지표당 현장이 2곳**이다. 3.4 의 현장 계층 bootstrap 이 성립하지 않는다.
2. **FDR 을 직접 못 잰다.** 유병률이 표집으로 만들어진 값이다 (3.4).
3. **507 내부**다. 안 본 현장이지 안 본 데이터 분포가 아니다.

**따라서 이름은 "잠금된 507 내부 확인셋" 이다.** 통과해도 신규 실제 현장
전향 평가가 **한 번 더** 필요하다. 이 이름을 쓰는 이유는 "holdout 통과" 라는
말이 최종 검증을 마쳤다는 뜻으로 읽히기 때문이다.

**동결 절차 — 라벨링·재측정보다 먼저 한다.**

1. 네 현장의 평가 대상 프레임 목록을 **manifest 파일**로 뽑는다
   (현장 · 클립 · 프레임 · 상황 ID · 정답 박스).
2. manifest 의 **SHA-256 을 아래 표와 `decisions.md` 에 적는다.**
3. 그 시점부터 **어떤 진단·임계 선택·프롬프트 수정에도 쓰지 않는다.**
4. **실패하면 개발로 되돌려 쓰지 말고 실패한 확인셋으로 남긴다.** 되돌려 쓰는
   순간 4.4 가 말하는 development set 이 되고, **남은 잠금 현장이 0 이 된다.**

| | 값 |
|---|---|
| manifest 경로 | `results/ppe_locked_manifest.json` — **아직 생성 전** |
| SHA-256 | **미정. 생성 즉시 여기에 적는다** |

> **순서에 이유가 있다.** 작업자 전수 주석을 먼저 하면 봉인 전에 이 네 현장을
> 들여다보게 된다. **프로토콜 동결 → manifest 해시 → 라벨링** 순이다.

## 5. 검증할 가설 하나 — **1차 검증 완료, 부분 성립**

`train_results.md` 1.6절에서 나왔다.

> **구역이 일정 크기 이상으로 잡히면 시스템이 작동한다.**
> A17 의 0.10~0.20 면적대에서 난간의 96.1% 를 찾고 빈 칸에 3.8% 만 헛경보했다
> (J 0.924). 3.4절의 합격 기준을 **넘는 유일한 구간**이다.

**검증했다** (`train_results.md` 1.7). 결과는 셋으로 갈린다.

| | 결과 |
|---|---|
| oracle 임계의 산물인가 | **아니다.** conf 0.005/0.01 고정에서도 유지된다 |
| 클립 난이도 교란인가 | **아니다.** 같은 클립 안 paired 비교에서 A17 +91.7%p, A04 +21.0%p |
| 다른 현장으로 일반화되는가 | **미검증.** A04 는 같은 방향, A21 은 반대. 양쪽 클립이 충분한 칸은 여전히 A17 하나 |

**남은 세 가지 제약.**

1. 효과가 **정상 구역 쪽에서만** 나온다. 미설치 구역 검출률은 면적대와 무관하게
   평평하다. "시스템이 작동한다" 보다 **"모델이 큰 난간을 잘 찾는다"** 가 정확하다.
2. 면적대 0.20~1.00 에서 **뒤집힌다**(정상 검출률 0.0%). `cov` 규칙이 큰 구역에서
   기계적으로 실패하는 것일 수 있다. 크기 하한을 정한다면 **상한도 함께** 정해야 한다.
3. 이 가설로 제품 범위를 좁히려면 **B-1 지정 ROI 가 전제**다 (3.1절). 미설치 구역은
   난간 검출로 ROI 를 만들 수 없으므로, "일정 크기 이상만 운영" 은 구역이 주어질
   때만 구현 가능하다.
