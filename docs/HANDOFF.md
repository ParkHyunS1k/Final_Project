## 2. 확정된 사실 — 다시 조사하지 말 것

### 데이터

1. **독립 현장이 4곳(A04/A08/A17/A21), 촬영 세션 10개, 프레임 1,912장.**
   프레임 수는 표본 수가 아니다. k=4 가 곧 leave-one-site-out.
2. **507 Training 파티션을 받아도 현장이 안 늘어난다.** 두 파티션의 영상 집합이
   동일하고 프레임만 8배다 (`phase0_results.md` 6-2).
3. **분할은 반드시 촬영 현장 단위.** 클립 단위로 하면 같은 세션을 여러 카메라로
   찍은 프레임이 흩어져 mAP50 이 0.898 로 부푼다(현장 단위 0.385).
4. **분할 seed 반복은 guardrail 에서 무의미하다.** 현장 4곳 k=4 라 각 폴드가 현장
   하나를 받고 `carve_val` 은 seed 를 안 받는다. seed 0/1/2 의 실험 집합이 동일함을
   확인했다. **반복 가능한 것은 학습 seed 뿐이다.**
5. **`carve_val` 이 편향돼 있다.** 세션을 크기순으로 결정적으로 고르고 현장 균형을
   안 맞춘다. **A08 은 세션이 1개뿐이라 어떤 폴드에서도 val 에 못 들어간다.**
   fold2 의 val 은 A04 세션뿐이다.
6. **`SO-01` 은 WS 상황에만 라벨된다.** UC 프레임의 "SO-01 0건" 은 **"없다" 가 아니라
   "라벨하지 않았다"** 이다. 그래서 프레임 단위 "난간 없음" 판정은 **성립하지 않는다.**
7. **507 미설치 평가셋은 성립한다.** `UC-01`(난간 있어야 하는데 없는 비계 한 칸)이
   `SO-01` 과 같은 현장에 있다 — A04 125 / A17 422 / A21 243 구역.
   `UC-04` 는 이동식 비계 **전체**라 단위가 다르니 섞지 말 것.
   `UC-03`/`UC-06`(난간 위 발판)은 **난간이 실제로 있으므로 negative 가 아니다.**
8. **71407 은 정상/불량이 다른 현장에서 촬영됐다** — `Y-04`=A18/A26 대 `N-04`=A32/A35,
   `Y-05`=A31 대 `N-05`=A26. **여기서 정상/불량 분류를 학습하면 현장 분류기가 된다.**
   파인튜닝에 쓰지 말 것. challenge set 으로만.
   **따라서 "71407 로 난간 현장을 4곳 → 8곳으로 늘린다" 는 예전 계획은 폐기됐다.**

   코드가 있는 시나리오는 `Y-04`(SO-01) / `N-01`(SO-04, A26) / `N-02`(SO-06, A26·32·34).
10. **SODA 는 못 쓴다.** `hook` 은 타워크레인 후크, `fence` 는 가설 울타리다.
11. **`WO-06` 은 안전고리가 아니라 작업자 몸통**, `UA-01` 은 전신. 507 라벨에 고리를

### 모델 진단

13. **회수율이 근본 문제다.** conf 0.001 에서도 A17 59.3 / A08 53.4 / A21 34.4 /
    A04 27.5%. **운용 임계 0.25 에서는 4현장 중 2곳이 사실상 아무것도 검출하지 않는다.**
    AP 가 conf≈0 까지 적분하므로 이것을 가려 왔다.
14. **경계 문제가 아니다.** IoU 임계를 0.5→0.1 로 풀어도 3~6%p 밖에 안 오르고
    합집합 IoU 도 A04 는 0.142 다. 칸을 잘못 나누는 게 아니라 **못 찾는다.**
15. **보조 클래스(`SO-02`/`WO-01`) 효과는 검출되지 않는다.** 폴드별 부호가 갈리고
    차이(0.028)가 폴드 간 std(0.19)보다 훨씬 작다. **유지한다.**
16. **`imgsz` 960 은 기각됐다.** 같은 FP/frame 예산에서 4폴드 평균 회수율이
    640 0.327 대 960 0.153. 현장별 부호가 난간 크기 순서와 단조로 갈리지만
    (A04 만 +0.117), 이는 해상도가 아니라 **테스트 시점 스케일 정렬**로 설명된다.
17. **val 기반 임계 선택은 클래스에 따라 갈린다.** `worker`(일반화됨) 0.839 대 0.700

**무엇을 하는가**: `SO-01` 구역(정상)과 `UC-01` 구역(미설치) crop 을 VLM 에 주고
"이 구역에 규정 안전난간이 있는가 / 어느 구성요소가 빠졌는가" 를 묻는다.
YOLO 와 **같은 구역·같은 현장 분할**로 재서 paired 비교한다.

**비교 기준은 이미 있다** — 위 1절 기준 B 표. 클립 macro 로 J 0.224~0.378,
적발 72.5~94.4% / 오경보 39.0~66.2% 다. VLM 도 **같은 클립 macro 로 집계**해야
paired 비교가 성립한다.

**모델 결정 — 라이선스가 정한다 (사실 21번).** `README.md` 7절 기술 스택을 이에 맞게 고쳤다 (2026-08-25). 예전에는 VARCO-VISION 2.0
1.7B 를 주력으로 지정했지만 **CC-BY-NC-4.0 이고, Qwen2.5-VL 3B 도 Qwen Research
License(비상업) 다.** 상업 이용을 염두에 두면 **Qwen2.5-VL 7B(Apache-2.0)가 유일한
주력 후보**이고, 12GB 에 4bit 로 들어간다. 3B·VARCO 는 실험 2(규모별 비교)의
**비상업 비교군**으로만 쓴다. 환경에는 `torch 2.6+cu124` 만 있고 `transformers` 는
없다 — 설치가 선행된다.

**착수 전 순서 — 0번을 건너뛰지 말 것.**

**~~0. 크롭을 눈으로 봐라~~ — 했다 (사실 35~38번, `train_results.md` 1.9).**
`scripts/zone_crops.py`. **결론이 계획을 바꿨다.** 가설은 "발끝막이판이 30px 라
안 보일 것" 이었는데, **발끝막이판은 아예 설치돼 있지 않았고** 난간기둥은
미설치 쪽에도 있었다. **4요소 중 판별 요소는 둘뿐**이다. 4요소 스키마를 그대로
쓰면 안 된다 — 아래 4절의 결정 항목을 먼저 정할 것.
그리고 **정상/미설치 구분 난이도가 A21 에서 확 오른다** (사실 37번).

**1. 면적 metadata baseline 을 반드시 붙여라.** `SO-01` 면적비 중앙값 0.0579 대
`UC-01` 0.1111 로 **2배 차이**가 난다 (`train_results.md` 1.5). 크롭 면적·종횡비만
쓰는 분류기가 먼저 몇 점을 내는지 재 두지 않으면, VLM 이 난간 구조를 본 것인지
**크롭 크기를 본 것인지 구분할 수 없다.** "전부 present" 퇴화 해도 함께 잰다
(`eval_protocol.md` 3.3 의 F1 0.846 / J −0.006 사례).

**2. 4요소 정답이 아직 없고, 4요소로 짜면 안 된다.** `SO-01`/`UC-01` 은 이진
라벨이다. 사람 정답이 필요하고 `README.md` 9절이 **라벨러 kappa 0.60** 과
**200~300장**을 요구한다. 2인 독립 라벨링 + 불일치 조정.
**단 스키마를 4요소로 그대로 짜면 상수 2개를 채점하게 된다** (사실 35·36번).
**A21 을 반드시 포함하고**(사실 37번), **면적 하한으로 슬리버 구역을 제외**할 것
(사실 38번).

**3. `absent`/`occluded`/`판정불가` 를 알람으로 어떻게 합칠지 먼저 고정하라.**
특히 **판정불가를 오경보·미탐·수동검토 중 어디로 셀지** 정해 두지 않으면, 모델
결과를 본 뒤에 규칙을 맞추게 된다.

**4. 집계는 클립 macro 로, 서브샘플링도 클립 단위로.** A04 정상 4,306구역은
20클립에서 나온다 — 구역을 늘려도 표본은 안 는다. 클립당 N장 균등 추출하면 몇 백
장으로 같은 정보를 얻는다. 이미지당 1~3초라 전수는 현장당 2~3.5시간이다.

**5. oracle ROI 임을 명시하라.** YOLO 와 같은 구역·같은 현장 분할로 paired 비교하되,
"구역이 주어졌을 때" 조건을 결과에 붙인다 (`eval_protocol.md` 3.1).

**절대 하지 말 것**: 71407 로 파인튜닝. 사실 8번 참조 — 현장 분류기가 된다.

**라벨 스키마는 미결이다 (사실 35·36번이 원안을 깼다).** 원안은 법령 4요소
(상부 난간대 / 중간 난간대 / 발끝막이판 / 난간기둥, 각각 `present / absent /
occluded` + `판정불가` 강제 선택지)였다. 그런데 **발끝막이판은 양쪽 다 없고
난간기둥은 양쪽 다 있다.** 세 안 중 하나를 골라야 한다 — 4절 참조.

### ~~② 크기 가설 검증~~ — **완료.** 부분 성립

`--fixed-conf` 와 클립 macro, paired 면적대 비교를 `zone_eval.py` 에 넣고 쟀다
(`train_results.md` 1.7, 로그 `outputs/zone_eval_clipmacro.log`).

- oracle 임계의 산물이 **아니다** — 고정 conf 에서도 유지된다.
- 클립 난이도 교란이 **아니다** — 같은 클립 안 paired 비교에서 A17 +91.7%p,
  A04 +21.0%p 로 방향이 같다.
- 다만 **정상 구역 쪽에서만** 나오고, 면적대 0.20~1.00 에서는 뒤집힌다.
- 다른 현장으로의 일반화는 **여전히 미검증** (사실 19번).

**남은 것**: 크기 하한을 제품 제약으로 쓰려면 (a) 상한도 정해야 하고
(b) B-1 지정 ROI 를 전제로 고정해야 한다 (`eval_protocol.md` 3.1).

### ③ `scale` 증강 확대 / 멀티스케일 학습 (GPU 2~3시간)

현장 간 난간 크기가 4배 차이(면적비 0.048~0.181)인데 `rtx4070.yaml` 의
`scale: 0.5` 로 흡수가 되는지 본다. 사실 16번에서 나온 방향이고 **아직 안 했다.**
`imgsz` 는 손대지 말 것(기각됨).

### ④ 이벤트 단위 평가 구현 (미구현)

`README.md` 9절 이 요구한다 — 트래킹 스무딩 후 이벤트 단위 precision/recall,
구역·시간당 오경보, 최초 탐지 지연. 프레임·구역 지표만으로는 영상 제품을
대표하지 못한다. `src/detect/tracking.py` 자리가 README 구조도에 이미 있다.

### ⑤ 새 현장 확보 (가장 큰 투자)

**모든 문제의 공통 원인이다.** 다만 71407 로는 늘릴 수 없다(사실 8번).

71407 은 전부 development set 이다 (`eval_protocol.md` 4.4).

### ⑥ 학습 seed 3회 반복 (GPU 5~6시간)

README 8절 요구사항. 현재 전부 seed 0 단일 실행이다. 분할 seed 는 무의미하므로
(사실 4번) 학습 seed 만 0/1/2 로 돌린다. **①~③ 이 끝나고 레시피가 확정된 뒤에 할 것.**

### ⑦ 라벨 누락률 정량화 — **실행했다. 가설 2 는 답이 나왔고 가설 1 은 열려 있다**

`scripts/unlabeled_probe.py` 를 돌렸다 (사실 31~34번, `train_results.md` 1.8,
산출물 `outputs/unlabeled/`). 원래 가설의 단순한 형태 — "작업자가 있는 칸에만
라벨" — 는 **기각됐다** (난간 3.38개/frame 중 작업자를 끼는 것 39.7%).

- **가설 2 (A04 FP 중 일부는 맞았는데 정답이 없어서 틀렸다고 세어진 것)**
  → **부분 성립하되 작다.** 상한 34%이고 물리적으로는 지상층 비계 **하나**다.
  **절반 이상(55.4%)은 유리 커튼월 반사**이고 이건 정직한 오검출이다.
  **A04 의 AP 0.084 를 라벨 누락으로 설명할 수 없다.**
- **가설 1 (미라벨 난간이 "난간은 배경" 신호가 되어 회수율을 누른다)**
  → **미검증. 이 probe 로는 원리상 답할 수 없다** (사실 34번).

**남은 작업 — 이것만 하면 된다.** 정답만 그린 프레임(`outputs/unlabeled/gt/`)을
현장·클립별로 층화 표집해 **보이는 칸 대 라벨된 칸**을 세서 누락률을 낸다.
모델을 거치지 않으므로 GPU 가 안 든다. 그 전까지는 낮은 회수율을 순수한
일반화 실패로만 해석하면 안 된다.

**새로 생긴 것 — A04 유리 반사는 별도 항목이다.** 제품이 사진 업로드로 가면
(3.⓪) 유리 외장 건물에서 같은 오검출이 반복된다. 리포트에 "유리에 비친 비계를
실물로 보고했다" 가 섞이면 신뢰가 무너진다. 판정 규칙이나 후처리가 필요하다.
A04 에만 있는 조건이라 **현장 4곳으로는 이 실패 모드를 일반화 검증할 수 없다**(⑤).

## 6. 방법론 — 이 프로젝트가 반복해서 빠진 함정

**전부 실제로 겪은 것이고, 매번 같은 종류다: 통계만 보고 확정했다.**

1. **크기 통계만으로 라벨의 의미를 확정하지 말 것.** `WO-06` 을 "부품" 으로,
   `Y-05` 의 `SO-02` 를 난간으로 단정한 것 둘 다 면적 통계만 보고 내린 판단이었고
   둘 다 틀렸다. **박스를 잘라 보는 데 10분이면 된다.** 그 10분을 아끼려다 모델
   하나를 잘못된 전제로 3.7시간 학습했다.
2. **면적비로 해상도를 정당화하려다 틀렸다.** "A04 면적비 0.048 이라 960 이 필요"
   라고 했는데, A17 은 0.062 로 거의 같은데 회수율이 3.5배였다. probe 로 기각됐다.
3. **A04 실패를 "칸 경계 모호성" 으로 가정했다가 틀렸다.** IoU 를 풀어도 안 올랐다.
4. **conf 0.25 로 진단해서 모순을 봤다.** AP 0.42 인 폴드가 프레임당 0.00개를
   검출했다. **AP 는 conf≈0 까지 적분한다** — 진단 임계를 AP 와 맞출 것.
5. **conf 그리드 하한을 0.01 로 둬서 잘못된 결론을 냈다.** 최적점이 경계에 걸려
   있었고, 0.001 로 내리자 "val 임계 선택 실패" 결론이 뒤집혔다.
   **최적값이 그리드 끝에서 나오면 그리드를 넓혀라.**
6. **평가 코드에 `imgsz` 를 하드코딩했다.** 안 고쳤으면 960 모델을 640 으로 재고
   있었을 것이다.
7. **정답 박스를 ROI 로 쓰면서 "제품 성능" 이라 부를 뻔했다.** oracle 조건은 반드시
   명시할 것.
8. **구역 수를 표본 수로 읽을 뻔했다.** A04 의 미설치 125구역은 **클립 2개**에서
   나온다. 인접 프레임은 독립이 아니다.

9. **"0건" 을 "없다" 로 읽었다.** C그룹 `UA-06` 을 0건으로 보고했는데, 실제로는
   715개가 있었고 `iter_frames` 가 keypoint 라서 버리고 있었다.
   **파서를 거친 0 은 "데이터에 없다" 가 아니라 "이 경로로는 안 보인다" 이다.**
   같은 실수를 사실 6번(SO-01 0건)에서 한 번 했는데, 그때는 라벨링 정책이었고
   이번엔 우리 코드였다. **집계가 0 이면 원본을 직접 열어 교차 확인할 것.**
10. **집계 단위를 정하지 않고 지표를 냈다.** 구역으로 나눈 적발률 90.1% 가 클립
    macro 로는 72.5% 였다. 프로토콜(4.1)이 클립 단위를 요구하고 있었는데도
    구현이 구역으로 나누고 있었다. **지표를 만들 때 분모가 독립 표본인지 먼저 볼 것.**
11. **"미매칭 예측 258개" 를 표본 258개로 읽을 뻔했다.** 클립·위치로 묶으니
    **물리적 위치 15곳**이었고, 상위 4곳이 78%였다. 그중 둘은 카메라만 다른
    같은 구조물이다. 8번과 같은 실수인데 이번엔 정답이 아니라 **예측** 쪽이었다.
    **분모가 프레임이면 무엇을 세든 표본 수가 아니다.**
12. **가설을 세운 도구로 그 가설을 검증할 수 없는 경우가 있다.** "미라벨 난간이
    회수율을 누른다" 를 **모델 예측**으로 확인하려 했는데, 회수율이 낮은 모델은
    바로 그 미라벨 난간을 예측하지 못한다. A08 미매칭 0개는 "라벨이 완전하다"
    가 아니라 **"모델이 라벨된 칸 말고는 못 찾는다"** 와 구분되지 않는다.
    **가설이 라벨의 성질이면 라벨만 봐야 한다.**
13. **가설의 단순한 형태가 그럴듯해 보여서 통계로 확인하기 전에 믿을 뻔했다.**
    A08·A21 프레임 몇 장에서 "작업자 칸에만 라벨" 로 보였는데, 라벨 통계로는
    난간 3.38개/frame 중 작업자를 끼는 것이 39.7%뿐이었다. **육안 표본 3장은
    가설을 만드는 데 쓰고, 확정하는 데 쓰지 마라.** 6절 1번의 반대 방향이다.
14. **"안 보일 것" 과 "없을 것" 을 구분하지 않았다.** 발끝막이판을 **"30px 라
    해상도 때문에 안 보일 것"** 으로 예상하고 크롭을 열었는데, 실제로는 **아예
    설치돼 있지 않았다.** 구역 폭이 1,000px 이 넘어도 없었다. 9번("0건" 을
    "없다" 로 읽었다)의 **정반대 방향**이다 — 이번엔 측정 한계로 설명될 것을
    가정했는데 실물이 없었다. **그리고 이 차이가 스키마를 바꿨다.**
15. **판별력을 확인하지 않고 정답 스키마를 설계했다.** 4요소를 채점 항목으로
    문서에 쓸 때 **각 요소가 양쪽 클래스에서 어떤 값을 갖는지 재지 않았다.**
    난간기둥은 정상·미설치 **양쪽에 있어서** 채점에 넣으면 정확도만 부풀린다.
    **정답 항목을 정하기 전에 그 항목의 클래스별 분포부터 볼 것.**

> **공통 교훈**: 새 코드를 쓰기 전에 원천을 눈으로 보고, 지표를 만들 때는
> **그 지표가 퇴화 해에서 어떤 값을 내는지** 먼저 확인하라. F1 0.85 가 J 0.00 인
> 경우를 실제로 만났다(정상 구역 0% 검출 + 모든 구역 알람).
> 그리고 **도구가 보여주지 않는 것을 없는 것으로 단정하지 마라.**
