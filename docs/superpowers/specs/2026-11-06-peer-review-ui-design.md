# 동료평가 화면과 규칙 변경 설계 (점수 UI 1·2)

이 문서는 2026-10-20 설계(docs/superpowers/specs/2026-10-20-peer-score-badges-design.md)의 일부를 대체한다.
여기에 적힌 내용이 우선하며, 적지 않은 규칙은 이전 문서를 따른다.
대체하는 부분은 평가 기간, 점수 척도, 등급, 공개 시점, 미제출 제재다.

## 왜

목표는 이 화면을 본 사람이 다음 프로젝트에서 더 잘하고 싶어지는 것이다(사용자, 2026-11-06).
이 화면은 성적표가 아니다. 다음에 무엇을 더 잘하면 되는지를 알려주는 화면이다.

점수는 프로젝트의 점수가 아니라 사람의 점수다. 팀원끼리 서로 평가하고, 내가 받은 평가가 내 점수가 된다.

동료평가는 팀원이 평가를 내야만 점수가 나온다. 예를 들어 3인 팀에서 한 명이 평가를 내지 않으면 나머지 두 명은 점수를 받지 못한다.
그래서 평가를 내지 않으면 다음 프로젝트를 막는 방식으로 제출을 강제한다.

## 범위

- **1. 평가 제출 폼:** 끝난 프로젝트에서 팀원 전원을 평가해 낸다.
- **2. 프로젝트별 내 결과:** 그 프로젝트에서 팀원에게 받은 내 점수, 등급, 문항별 평균, 뱃지, 평가 진행 상태를 본다.
- **규칙 변경:** 서버 규칙과 API를 바꾼다. 내용은 아래 '사용자 결정'에 있다.
- **범위 밖:**
  - 3번 작업인 '내 기록' 화면(사이드바)은 다음 작업이다. 여기서는 그 화면이 기댈 API 규칙만 맞춘다.
  - 공유 링크는 만들지 않는다.
  - 평가 내용 신고와 이의 제기는 하지 않는다.
  - 운영자가 제재를 풀어 주는 기능은 하지 않는다.

## 사용자 결정 (2026-11-06)

| 항목 | 결정 |
|---|---|
| 평가 기간 | 프로젝트가 끝난 시각(완주 시각, 없으면 기한)부터 **24시간**. 이전에는 7일이었다. |
| 점수 척도 | **5점제**. 세 문항(기여도·소통·약속 이행)마다 받은 평균을 낸 뒤, 그 세 평균을 다시 평균 낸다. 소수 첫째 자리에서 반올림한다. ×20으로 100점 만점을 만들지 않는다. |
| 등급 | **S** 4.8 이상 · **A** 4.0~4.7 · **B** 3.0~3.9 · **C** 2.0~2.9 · **D** 1.0~1.9 |
| E 등급 | 계정 단위 등급이다. 프로젝트를 시작한 적이 없거나 점수가 한 번도 공개되지 않은 사람이 받는다. 프로젝트별 결과에는 나오지 않는다. |
| 공개 시점 | **전원이 제출했을 때**와 **24시간이 지났을 때** 중 빠른 쪽. 평가자가 2명 이상이어야 공개한다는 조건은 그대로다. |
| 결과 보기 조건 | 내가 평가를 내야 내 결과가 보인다. |
| 미제출 제재 | 24시간 안에 내지 않으면 미제출 1회로 센다. 계정 전체에 누적한다. 1회는 **7일**, 2회는 **30일**, 3회는 **영구** 금지다. |
| 금지 범위 | 새 프로젝트 만들기, 참여 신청, 초대 수락, 준비 상태 프로젝트 시작을 막는다. 이미 진행 중인 프로젝트는 계속할 수 있다. |
| 금지 시작 | 그 프로젝트의 평가 기간이 끝난 시각부터 센다. |
| 영구 금지 해제 | 해제 기능이 없다. 사용자도 이를 알고 동의했다. |

## 규칙 상세

### 점수와 등급 (lib/score.ts)

- **문항 평균:** 그 사람이 받은 평가에서 해당 문항의 평균을 낸다.
- **점수:** 세 문항 평균의 평균을 소수 첫째 자리로 반올림한다. 값의 범위는 1.0~5.0이다.
- **등급:** 반올림한 점수로 판정한다. 아래 기준을 위에서부터 차례로 보고 처음 맞는 등급을 준다. 반올림했기 때문에 경계(예: 4.75)가 비지 않는다.
  - S: 4.8 이상
  - A: 4.0 이상
  - B: 3.0 이상
  - C: 2.0 이상
  - 그 밖: D
- **breakdown:** 문항마다 `{ key, label, average }`를 준다. average는 소수 첫째 자리다. 이전의 `points`(×20÷3)는 없앤다.
- **개인 뱃지 기준:** 문항 평균 4.5 이상으로 그대로 둔다. 핵심 기여자, 소통왕, 약속 지킴이가 여기에 해당한다.

### 평가 기간과 공개

- `REVIEW_DAYS = 7`을 24시간으로 바꾼다. 저장할 때 다시 확인하는 SQL(`OPEN_WINDOW`)의 `interval '7 days'`도 `'24 hours'`로 바꾼다.
- **평가를 낼 수 있는 때(제출 가능):** `endAt ≤ 지금 < endAt + 24h`이고 내가 아직 내지 않았을 때다.
- **결과 공개(closed):** 아래 둘 중 하나가 먼저 일어날 때다.
  - 지금 ≥ `endAt + 24h`
  - 참여 중인 멤버 전원이 제출했다. 여기서 멤버는 `left_at`이 없는 사람이고, 평가할 대상이 있는 사람만 센다.
- 전원이 제출해서 일찍 공개되더라도 `closesAt`(평가 마감 시각)은 `endAt + 24h`로 그대로 둔다. 개인 뱃지의 earnedAt은 실제로 공개된 시각에 맞춘다. 이 시각은 일찍 공개됐으면 마지막 제출 시각이고, 아니면 closesAt이다.
- 익명성 규칙은 이전과 같다.
  - 평가자가 2명 미만이면 점수와 등급은 null이다.
  - 평가자 수는 공개 뒤에만 준다.
  - 팀장도 다른 사람의 결과를 볼 수 없다.

### 내가 내야 결과가 보인다

- 공개 뒤에 아래 두 조건이 모두 맞으면 결과를 숨긴다.
  - 그 프로젝트에서 평가할 대상이 있었다.
  - 나는 평가를 내지 않았다.
- 숨기는 것은 내 점수, 등급, breakdown, 개인 뱃지 세 개다. 팀 뱃지(7일 완주 등)는 그대로 보인다.
- 응답에는 `review.hidden: true`로 이 상태를 알린다.
- 솔로처럼 평가할 대상이 없던 사람은 이 조건과 상관없다.
- `SANCTION_FROM` 전에 끝난 프로젝트는 숨기지 않는다. 그때는 평가 화면이 없어 낼 방법이 없었다(빌더 확인에서 나온 내 판단).
- `/api/score/me`에서도 결과를 숨긴 프로젝트의 점수와 개인 뱃지는 세지 않는다.

### 미제출 제재

- **미제출 1회의 정의:** 프로젝트 하나가 아래 다섯 조건을 모두 만족하면 미제출 1회다.
  - 평가 기간이 시간으로 끝났다. 지금 ≥ closesAt이다.
  - 나는 참여 중인 멤버였다.
  - 평가할 대상이 1명 이상 있었다.
  - 나는 평가를 내지 않았다.
  - 프로젝트가 끝난 시각이 **제재 시작 시각(`SANCTION_FROM`) 이후**다.
- **`SANCTION_FROM`:** 배포 날짜를 상수로 둔다. 규칙이 7일에서 24시간으로 바뀌면서 이전 규칙으로 끝난 프로젝트가 한꺼번에 미제출로 잡히는 것을 막기 위해서다.
- **저장하지 않는다.** 끝난 프로젝트와 `peer_review_submissions`를 비교해서 그때그때 계산한다. 새 테이블이나 마이그레이션은 없다.
- **기간 계산:** 미제출을 closesAt 순으로 정렬한다. k번째 미제출의 금지는 closesAt_k부터 이어진다.
  - k=1: 7일
  - k=2: 30일
  - k≥3: 영구
- 지금이 어느 금지 기간 안에 있으면 금지 상태다. 응답은 `{ until: ISO | null, permanent: boolean, misses: number } | null` 모양이다.
- **서버 거절:** 아래 세 경로에서 금지 상태면 403으로 거절한다. 메시지 예는 "동료평가를 내지 않아 11월 13일 14:00까지 새 프로젝트를 만들 수 없습니다."이고, 영구 금지면 날짜 대신 영구라고 쓴다.
  - `POST /api/projects {action:'create'}`
  - `POST /api/projects {action:'accept'}`
  - `POST /api/teams {action:'request'}`
  - `POST /api/sprint {action:'start'}`로 금지 전에 만들어 둔 준비 프로젝트를 시작할 때(사용자 결정 2026-11-06). 시작은 팀장이 하므로 팀장의 금지 상태를 본다. 준비 화면의 시작 버튼도 금지 안내와 함께 끈다.
  - `POST /api/projects {action:'decideJoin'}`로 금지된 사람의 신청을 승인할 때. 금지 전에 넣어 둔 신청으로 새 팀에 들어가는 것을 막는다(빌더 확인에서 나온 내 판단). 팀장 화면에는 "이 사람은 지금 참여할 수 없어요"를 보여주고 거절만 할 수 있게 한다.
- **화면용 정보:** 이 금지 상태를 `GET /api/projects` 응답에 `restriction`으로 같이 준다.

## 화면

### 놓는 곳: 끝난 프로젝트의 홈

- 진행 중일 때 카운트다운이 있던 자리에 평가 카드를 놓는다.
- 캘린더와 체크인 현황은 아래에 그대로 둔다.
- 끝났다는 판단은 서버의 `review.status !== 'not_open'`을 따른다.
- 시각 판단은 `useServerNow`로 한다. 렌더링 중에 `Date.now()`로 정하지 않는다.

### 카드 상태

| 상태 | 보이는 것 |
|---|---|
| 평가 중, 미제출 | "평가 카드를 채워야 결과를 볼 수 있어요." 평가는 아래 **평가 모달**에서 한다. 모달의 카드가 마감까지 남은 시간을 초 단위로 센다. 기존 tension 단계와 색을 그대로 쓴다. 문구는 "24시간 안에 내지 않으면 7일 동안 새 프로젝트를 시작할 수 없어요"처럼 다음 미제출 횟수에 맞춰 바뀐다. |
| 평가 중, 제출함 | "평가를 냈어요. 팀원 전원이 내거나 {마감 시각}이 되면 결과가 열려요." 그리고 '평가 완료' 뱃지. |
| 공개, 점수 있음 | **결과 카드** (아래) |
| 공개, 평가자 2명 미만 | "평가한 팀원이 2명이 안 돼 이번에는 점수가 없어요." 그리고 팀 뱃지. |
| 공개, 내가 미제출 | "평가를 내지 않아 이번 결과는 볼 수 없어요." 그리고 금지 상태(기간 또는 영구). |
| 평가할 대상 없음 (솔로) | 평가 폼 없이 팀 뱃지만 보여준다. |

### 평가 모달 (사용자 결정 2026-11-06, 평가 폼을 대체)

- 아직 낼 평가가 있으면 작업 공간 어느 화면이든(팀 찾기·만들기 포함) 들어오자마자 모달을 띄운다. 배경은 흐리게 하고 다른 기능은 쓸 수 없다.
- Esc·뒤로로 닫히지 않는다. 닫히면 바로 다시 연다. 평가를 다 내야 사라진다.
- 팀원 한 명씩 카드로 보여준다. 카드에는 이름, 순서(1 / 2), 세 문항의 별 다섯 개가 있다. 별의 왼쪽 반은 .5점, 오른쪽 반은 1점이라 0.5~5를 0.5점 단위로 고른다(사용자 결정 2026-11-06). 고른 값은 숫자로도 보인다. 0.5~5 열 칸짜리 라디오 그룹이라 키보드 화살표로 조작할 수 있다.
- 세 문항을 다 고르면 '다음'이 켜지고 다음 사람 카드로 넘어간다. '이전'으로 돌아가도 고른 값은 남는다.
- 마지막 카드의 '평가 제출'은 확인 창("제출하면 고칠 수 없어요.")을 거쳐 전원 평가를 한 번에 낸다(API는 그대로).
- 낼 프로젝트가 여럿이면 하나씩 이어서 띄운다. 목록은 GET /api/projects의 `reviewPending`이며 처음, 30초마다, 창으로 돌아올 때, 홈 카드가 낼 평가를 볼 때 서버에서 다시 받는다(어느 화면에서든 프로젝트가 끝나면 뜬다).
- 모달은 마감 시각이 지나거나, 창으로 돌아오거나, 제출이 거절되면(다른 탭에서 이미 냄 등) 서버에 다시 묻고, 더 낼 게 없으면 닫힌다.
- 남은 시간은 GET /api/score가 주는 서버 시각(`asOf`)으로 센다.
- 막는 것은 화면이다. 서버가 막는 것은 지금처럼 미제출 제재뿐이다.

### 결과 카드: 다음에 더 잘하고 싶게

- **크게 보이는 것:** 등급 글자와 점수(예: `A 4.1 / 5`).
- **문항 세 줄:** 문항마다 평균을 막대로 보여준다(예: 기여도 4.7, 소통 3.3, 약속 이행 4.3).
  - 가장 낮은 문항을 강조하고 "다음 프로젝트에선 **소통**을 챙겨 보세요" 한 줄을 붙인다.
  - 낮은 문항이 둘 이상 같으면 문항 순서상 앞의 것을 고른다.
  - 세 문항이 모두 4.5 이상이면 강조하지 않고 "세 문항 모두 4.5 이상이에요"라고 쓴다.
- **다음 등급까지:** 예를 들어 "S까지 0.7". S면 이 줄을 뺀다.
- **뱃지:** 받은 뱃지는 진하게, 못 받은 뱃지는 흐리게 보여준다. 못 받은 뱃지에는 조건 설명을 붙여 다음 목표로 보이게 한다.
- **평가자 수:** "팀원 3명이 평가했어요"처럼 보여준다.
- 남과 비교하는 정보(팀 평균, 순위)는 없다. 익명성 때문이다.

### 제재 안내

- `restriction`이 있으면 두 화면에 안내 줄을 띄우고 버튼을 끈다.
  - 새 프로젝트 만들기 화면: 만들기 버튼
  - 팀 찾기: 참여 신청 버튼
- 문구는 금지가 풀리는 시각, 또는 영구 금지임을 쓴다.

### 첫 화면

- 로그인 후 평가 기간 중인데 아직 내지 않은 프로젝트가 있으면 그 프로젝트의 홈을 먼저 연다. 그 위에 평가 모달이 뜬다.
- 이 규칙이 다른 첫 화면 규칙보다 우선한다. 예를 들어 '진행 중인 프로젝트가 없으면 팀 찾기' 규칙보다 먼저다.

## API 변경 요약

- **`GET/POST /api/score`:**
  - `score`는 1.0~5.0이다.
  - `grade`는 `'S'|'A'|'B'|'C'|'D'|null`이다.
  - `breakdown`은 `[{ key, label, average }]`이다.
  - `review`에 `hidden: boolean`을 추가한다. 나머지 필드는 그대로다.
  - `review.status === 'closed'`의 뜻이 '결과 공개'로 바뀐다. 시간이 지났거나 전원이 냈을 때다.
- **`GET /api/projects`:** `restriction: { until, permanent, misses } | null`을 추가한다.
- **`GET /api/score/me`:**
  - 등급 순서에 D를 추가한다.
  - 확정된 점수가 하나도 없으면 `bestGrade: 'E'`를 준다.
  - `totalScore`는 3번 작업에서 다시 정한다. 이번에는 바꾸지 않는다.
- **거절 응답:** create, accept, request, start, 금지된 사람의 decideJoin 승인은 403을 준다.

## 이전 데이터

- `peer_reviews`에 저장된 원본을 그대로 쓴다. 0.5점 단위를 담으려고 세 문항 열을 integer에서 real로 바꿨다(마이그레이션 0008, 기존 정수 값은 그대로). 서버는 0.5~5의 0.5 배수만 받는다.
- 배포하는 순간 끝난 지 24시간이 넘은 프로젝트는 곧바로 결과가 공개된다. 이전 기준이었던 7일이 아직 남아 있던 프로젝트도 마찬가지다.
- 그런 프로젝트는 `SANCTION_FROM` 전에 끝났으므로 미제출로 세지 않는다.

## 검증

- **단위 테스트 (lib/score):**
  - 5점 점수와 반올림
  - 등급 경계: 4.75→4.8 S, 4.0 A, 3.95→4.0 A, 1.0 D
  - 24시간 기간
  - 전원 제출 시 일찍 공개
  - hidden 조건
  - 제재 계산: 0~3회, 기간 경계, `SANCTION_FROM` 이전 제외
- **API 테스트 (PGlite):**
  - 24시간 뒤 제출하면 거절
  - 전원이 제출하면 바로 점수가 나옴
  - 미제출자는 hidden
  - 금지 상태에서 create, accept, request, start, decideJoin 승인이 403
  - 금지 기간이 지나면 허용
  - 계정 분리: 남의 금지가 나에게 영향을 주지 않음
- **렌더 테스트:** 평가 폼, 결과 카드, 각 상태 문구.
- **브라우저 확인 (로컬 PGlite, 계정 3개):**
  - 끝난 프로젝트에서 평가 제출
  - 결과 공개
  - 미제출 계정의 금지 안내
  - 밝은 화면과 어두운 화면, 375px 폭
