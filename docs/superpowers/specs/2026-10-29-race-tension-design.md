# 홈 화면 긴장감: 업무 마감 카운트다운

2026-10-29 · UI 세션 · 피드백 7("시간이 흐르는 걸 표현하는 애니메이션")

## 왜

7일 스프린트인데 진행 중 화면이 차분하고 정적이라 컨셉과 맞지 않는다. 사용자가 원하는 것(사용자 말):

- 프로젝트 중에는 계속 "지금 이 순간에도 시간이 흘러가고 있다"는 느낌.
- 마감이 다가올 때 아무 효과가 없어 긴장이 풀리기 쉽다. 프로젝트 마감과 각 업무 마감 모두에 긴장감.

시안: `.superpowers/brainstorm/10548-1793278233/content/tension-b-v7.html`(로컬, 커밋 안 함). 사용자가 B안을 골랐고 v7까지 다듬었다.

## 목표 · 비목표 · 하지 말 것

- 목표: 진행 중(active) 프로젝트 홈에서 **내 업무 마감**을 초 단위로 크게 세고, 마감이 가까울수록 화면이 붉어지고 마감 직전엔 깜빡인다.
- 비목표: 서버·API·DB 변경, 소리·브라우저 알림·메일, 업무 시작 시각 같은 새 데이터, 업무 탭 개편.
- 하지 말 것: 화면 전체 깜빡임, 초당 3회 이상 깜빡임, 끝없이 깜빡임(마감 초과 후), 글자를 읽기 어렵게 만드는 배경.

## 홈 화면 구성 (진행 중 프로젝트, 위에서 아래로)

1. **상단 바**(그대로): 프로젝트 이름, DAY n/7, `RaceClock`(프로젝트 전체 마감), [진행 보고].
2. **큰 카운트다운**(새로)
   - 문구: `{업무명} 마감까지`. 업무명은 강조색.
   - 숫자: `HH:MM:SS`(남은 시간이 24시간을 넘어도 시간 단위로, 예 `52:10:03`). 초가 바뀔 때 초 자리만 짧게 떨어지는 애니메이션.
   - 아래 작은 글씨(마감 시각, 다음 업무)는 **두지 않는다**(사용자 결정).
3. **일차별 캘린더**(`DeadlineCalendar`, 구조 유지): 오늘 칸 강조와 '지금' 막대는 이미 있다. 추가: 오늘 칸 `aria-current="date"`, 칸 안 업무 칩을 각자 마감 기준으로 색 변경(아래 규칙), 완료 업무는 취소선.
4. **두 칸**(좌우, 좁은 화면에선 위아래)
   - 왼쪽 **팀원 체크인 현황**(새로, 기존 '최근 진행 보고'를 대신함): 참여 중인 팀원마다 이름, 지금 업무(`laneTask`)와 `dueLabel`, 오늘(KST) 진행 보고 여부 배지 '오늘 체크인 완료' / '아직 체크인 안 함'. 내 줄에는 '나'.
   - 오른쪽 **회의 제안**(기존 그대로).

**홈에서 빠지는 것**(사용자 결정): 큰 숫자 3개(완료 업무·공수·병목), 병목 알림, 팀 레인, 최근 진행 보고 목록. 업무 탭의 '병목' 태그·표시는 그대로 둔다. 8시간 가정 안내 문구는 팀 레인과 함께 빠진다.

준비 중(draft) 홈은 지금과 같다. 완주·기한 종료 홈도 **새 구성**(캘린더 + 체크인 현황 + 회의 제안)을 쓰되 큰 카운트다운과 모든 긴장 효과(배경·테두리·칩 색·깜빡임)는 없다. (Claude 판단: 상태별로 옛 구성을 남기지 않는다.)

홈 캘린더의 병목 깃발(`blocked` 클래스·Flag 아이콘)도 뺀다. 홈에서 병목 표시를 빼기로 한 결정에 맞추고, 새 칩 색(주황·빨강)과 의미가 섞이지 않게 한다. (Claude 판단) 그 결과 `RaceHome`은 `plan`·`sprintPulse`에 기대지 않는다.

## 카운트다운 대상 업무

`focusTask(tasks, me.person)`:

- 후보: `person === me.person`, `!done`, `!deferred`, `dueAt` 있음.
- 그중 `dueAt`이 가장 이른 업무. 마감이 지난 미완료 업무도 후보다(가장 이르므로 먼저 잡힌다).
- 완료(어느 경로든 서버 `done`)하면 다음 재조회부터 바로 다음 업무를 센다(사용자 결정: 완료 즉시 다음 업무).
- 후보가 없으면 **대기 중**: 숫자 대신 회색 '대기 중', 긴장 효과 없음. 문구(Claude 판단):
  - 내 업무가 있었고 모두 완료: `내 업무 모두 완료 · 대기 중`
  - 미완료 업무가 있지만 모두 마감 미정: `마감이 정해진 내 업무 없음 · 대기 중`
  - 나에게 배정된 업무가 없음: `배정된 내 업무 없음 · 대기 중`
  - 프로젝트에 업무가 하나도 없으면 지금처럼 `업무가 아직 없습니다` 안내와 [업무로 이동] 버튼을 카운트다운 자리에 둔다.

참고: 이 제품에서 '진행 보고(체크인)'는 진행 상황·남은 공수 기록이고, 업무 완료는 업무 상태를 완료로 바꾸는 별도 동작이다. 카운트다운은 **완료**를 기준으로 넘어간다.

## 긴장 규칙

남은 시간 `left = dueAt − 서버 기준 현재`(`useServerNow(asOf)`, 1초마다 갱신). 브라우저 시계로 판단하지 않는다.

| 구간 | 숫자 색 | 배경 붉은 기 | 테두리 |
|---|---|---|---|
| left > 72h | 기본 | 없음 | 없음 |
| 24h < left ≤ 72h | 주황(`--heat`) | 점점 진해짐 | 없음 |
| 1h < left ≤ 24h | 빨강 | 점점 진해짐 | 숨쉬듯 붉은 빛(2.4초 주기) |
| 0 < left ≤ 1h | 빨강, 초당 1회 깜빡 | 최대에 가까움 | 붉은 테두리 초당 1회 깜빡 |
| left ≤ 0 (마감 초과) | 빨강 고정, 문구 `{업무명} 마감 초과`, 숫자 `+HH:MM:SS`(지난 시간) | 최대 | 붉은 테두리 고정(깜빡임 없음) |
| 대기 중 | 회색 | 없음 | 없음 |

- 배경 붉은 기 `tint = clamp(1 − left/72h, 0, 1)^1.4`. 연속으로 변한다. 다음 업무로 넘어가면 그 업무 기준으로 다시 계산되므로 자연히 옅어진다(사용자 결정: 업무마다 다시 시작).
- 적용 범위: 진행 중 프로젝트의 **작업 화면 본문 전체**(홈·업무·프로젝트 탭 공통). 큰 카운트다운은 홈에만. (Claude 판단: "계속 시간이 흐르는 느낌"은 탭을 옮겨도 유지돼야 한다.)
- 배경은 본문 뒤 장식 레이어(`pointer-events:none`, 글자 대비에 영향 없게 가장자리 위주 방사형 + 아주 옅은 전체 틴트). 다크·라이트 모두.
- 깜빡임은 테두리와 큰 숫자에만, 초당 1회(광과민 기준 초당 3회 미만). `prefers-reduced-motion`이면 움직임 없이 색·테두리만(기존 전역 규칙).

캘린더 칩 규칙(각 업무 자기 마감 기준): ≤24h 주황, ≤6h 빨강, ≤1h 초당 1회 깜빡, 마감 초과 빨강 고정, 완료 취소선. 칩 색·깜빡임은 진행 중(active)일 때만 켠다. 완주·기한 종료 캘린더는 완료 취소선만.

## 오늘 체크인 판정

`checkedInToday(checkins, tasks, person, now)`: `checkins` 중 `task_id`의 업무 담당자가 `person`이고 `created_at`의 KST 날짜가 `now`의 KST 날짜와 같은 것이 있으면 완료. 팀장이 팀원 업무로 대신 보고한 경우도 그 담당자의 체크인으로 본다.

한계: 서버 상태의 `checkins`는 프로젝트 전체 최근 20건이다. 하루에 20건을 넘게 보고하면 이른 보고가 잘려 '안 함'으로 보일 수 있다. 2~4인 팀에서는 드물어 이번에는 그대로 두고 코드에 `ponytail:` 주석으로 남긴다(필요하면 서버에서 멤버별 마지막 보고 시각을 내려준다).
