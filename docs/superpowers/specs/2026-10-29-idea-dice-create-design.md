# 프로젝트 만들기: 주사위 단어 · 범위 슬라이더

2026-10-29 · UI 세션 · 피드백 1~4(템플릿·랜덤, 마우스 우선, 범위 슬라이드, 필수 결과물 없음)

전제: 솔로플레이·필수 결과물 제거(66fa758)는 이미 main에 있다. 서버는 `deliverables`를 읽지 않고 1명이어도 시작할 수 있다.

## 목표

키보드를 거의 쓰지 않고 클릭 몇 번으로 7일 프로젝트를 만든다. AI를 쓰지 않는다.
주사위가 단어 3개를 무작위로 던지고, 사용자는 떠오르는 게 있을 때까지 계속 굴린다.

성공 기준: 🎲 → 확인 체크 → 만들기, 키보드 입력 0회로 준비 상태 프로젝트가 생성되고 재조회된다.

## 사용자 결정

- 주사위 = 단어 3개 무작위(조합도 무작위). 단어마다 잠금 가능, 잠근 단어는 다시 굴려도 유지(2026-10-15).
- 떠오른 아이디어 한 줄 입력칸을 두되 비워도 만들 수 있다(C안).
- 기능 범위는 5단계 슬라이더: 핵심 기능 · MVP · 테스트 · 데모 · 배포. 1단계·5단계와 MVP·데모는 사용자가 고정했고, 3단계는 MVP와 데모 사이의 사용자 검증을 '테스트'라는 이름으로 넣었다.
- 예상 무게(인원·시간 대비 여유) 표시는 넣지 않는다.
- 필수 결과물 입력란은 없앤다(서버가 이미 받지 않음).

## 화면

만들기 패널 하나에 위에서 아래로:

1. **주사위** — 단어 칩 3개와 🎲 버튼. 칩마다 🔒 토글(`aria-pressed`). 처음 열면 이미 한 번 굴린 상태.
   굴릴 때 칩이 짧게 흔들리는 애니메이션, `prefers-reduced-motion`이면 즉시 교체(기존 전역 규칙).
   3개 모두 잠그면 🎲 비활성.
2. **떠오른 아이디어 한 줄** — 선택, `maxLength=100`, placeholder "떠오른 아이디어 한 줄 (비워도 돼요)".
3. **범위 슬라이더** — `<input type="range" min=1 max=5 step=1>`, 기본 2(MVP). 눈금 아래 단계 이름 5개(눌러도 선택).
   아래에 고른 단계의 기능 범위 문장과 완료 기준을 보여준다.
4. **확인 체크 + [프로젝트 만들기]** — 체크 문구에서 '결과물'을 뺀다. 안내문의 '최소 2명' 문구를 솔로플레이에 맞게 바꾼다:
   "만들면 준비 상태로 저장되고, 팀장이 시작한 시각부터 7일이 흐릅니다. 혼자서도 시작할 수 있어요."

## 범위 5단계

| 단계 | 이름 | 기능 범위 문장 | 완료 기준 |
|---|---|---|---|
| 1 | 핵심 기능 | 핵심 기능 1개가 처음부터 끝까지 동작한다 | 핵심 기능 1개를 끊김 없이 시연할 수 있다 |
| 2 | MVP | 사용자가 들어와서 목적을 이루고 나가는 흐름 하나를 완성한다 | 사용자 역할로 처음부터 끝까지 한 번에 해낼 수 있다 |
| 3 | 테스트 | 팀 밖 사람 3명에게 써보게 하고 가장 큰 불편 하나를 고친다 | 사용자 3명의 피드백과 고친 내용을 보여줄 수 있다 |
| 4 | 데모 | 처음 보는 사람 앞에서 5분 안에 시연할 수 있게 다듬는다 | 시연 영상이나 발표 자료로 전체 흐름을 보여줄 수 있다 |
| 5 | 배포 | 배포해서 누구나 주소로 들어와 쓸 수 있게 한다 | 배포 주소에서 팀 밖의 사람이 직접 써볼 수 있다 |

단계는 누적이다(3단계 = 핵심 기능·MVP·테스트까지). 완료 기준은 고른 단계의 것 하나만 보낸다.

## 서버로 보내는 값

`POST /api/projects {action:'create'}`. 서버 파일은 바꾸지 않는다.

| 필드 | 아이디어 입력 시 | 비웠을 때 |
|---|---|---|
| title | 입력한 한 줄(trim) | `고양이 · 영수증 · 지도` |
| goal | 입력한 한 줄 | `'고양이·영수증·지도' 조합에서 떠올린 서비스를 7일 안에 만든다` |
| scope | `[MVP] 사용자가 들어와서 …` (단계 이름 + 문장) | 같음 |
| completionCriteria | 단계 완료 기준 | 같음 |
| duration / agreed | 7 / 체크 여부 | 같음 |

- `deliverables`는 보내지 않는다.
- 만들기 화면에 상세 편집은 두지 않는다. 문장 수정은 아래 '목표 고치기'에서 한다.
- 서버 오류 메시지는 기존처럼 패널 상단 `role="alert"`로 보여준다.

## 목표 고치기 (준비 중, 팀장)

아이디어를 비우고 만들면 목표가 단어 조합 문장으로 남는다. 서버에는 `editGoal`(POST /api/sprint, 준비 중만)이 있지만 이를 부르는 화면이 없으므로 함께 만든다.

- 위치: 프로젝트 메뉴의 `ProjectDetails` 카드. `me.role === 'owner'`이고 `lifecycle === 'draft'`일 때만 [목표 고치기] 버튼.
- 폼: 이름(input, 100) · 목표(textarea, 1000) · 범위 슬라이더 · 기능 범위(textarea, 2000) · 완료 기준(textarea, 2000).
  초깃값은 `state.agreement`. 슬라이더 초깃값은 scope 앞 `[단계명]`으로 찾고, 없으면 2(MVP).
  슬라이더를 움직이면 기능 범위·완료 기준 칸을 그 단계 문장으로 덮어쓴다(직접 쓴 문장을 지울 수 있다는 것을 슬라이더 옆에 표시).
- 저장: `{action:'editGoal', projectId, revision, title, goal, scope, completionCriteria, duration: policy.durationDays}`.
  성공하면 재조회. 안내: "저장하면 목표 버전이 올라가고 팀원은 다시 동의해야 합니다."
- 실패: 서버 메시지 그대로 표시 후 재조회(버전 충돌 409 포함). 브라우저에서 권한·상태를 판단하지 않고 서버 거절을 따른다(버튼 노출 조건은 편의용).

## 구성

- `web/lib/idea-dice.ts` (신규, 순수 함수)
  - `WORDS`: 일상 명사 약 150개, 중복 없음.
  - `roll(current: string[], locked: boolean[], random = Math.random): string[]` — 잠기지 않은 칸만 새 단어로, 3개가 서로 다르게.
  - `SCOPE_LEVELS`: 위 5단계 `{ name, scope, criteria }`.
  - `createBody({ words, idea, level, agreed })` → 위 표의 요청 본문.
  - `levelOf(scope: string): number` — `[단계명]` 접두어로 단계 찾기, 없으면 2.
- `web/components/project-create.tsx` (신규) — 만들기 화면. `onCreated(projectId)`, `onError(message)`를 받는다.
- `web/components/scope-slider.tsx` (신규) — 만들기·목표 고치기가 같이 쓰는 5단계 슬라이더.
- `ProjectDetails`(project-workspace.tsx) — 목표 고치기 폼 추가. `app/workspace/page.tsx`가 `agreement`·`policy`·`revision`·`refresh`를 넘긴다.
- `web/components/project-workspace.tsx` — 기존 인라인 폼과 `create()`를 `ProjectCreate`로 교체.
- `web/app/globals.css` — `.dice-*`, `.scope-*` 스타일. 기존 토큰(`--gray-*`, `--heat-*`)만 사용, 다크·라이트 모두.

## 검증

- `web/tests/idea-dice.test.ts`
  - `WORDS` 중복 없음, 150개 안팎.
  - `roll` 결과 3개가 서로 다르다(고정 시드 반복).
  - 잠근 칸은 그대로, 전부 잠그면 결과 동일.
  - `createBody`: 아이디어 유무별 title/goal, 공백만 입력은 빈 것으로 처리, `deliverables` 없음, 모든 단계에서 서버 길이 제한(title 100, goal 1000, scope·criteria 2000) 이내.
  - `levelOf`: 각 단계 접두어, 접두어 없음 → 2.
- 로컬 PGlite(`workspace-ui`): 키보드 없이 만들기 → 준비 상태 화면 → 새로고침 후 재조회. 목표 고치기 저장 → 재조회 시 바뀐 문장·목표 버전 +1, 팀원 계정(3111)에는 버튼이 안 보이고 재동의 안내가 뜬다. 다크·라이트, 375px 폭.
- 린트는 기존 오류 수보다 늘지 않을 것. 전체 테스트·빌드 통과.

## 하지 않는 것

- AI 주제 생성, 단어 카테고리 분류, 단어 목록 서버 저장.
- 예상 무게 표시, 결과물 입력, 만들기 화면 안의 상세 편집, 진행 중(active) 목표 수정.
- 서버·DB 변경(범위 단계 별도 칼럼 저장 등). 팀 목록에 단계가 필요하면 scope 문장 앞 `[단계명]`을 쓴다.
