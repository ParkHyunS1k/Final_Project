# 작업 화면 레이스 재설계

날짜: 2026-10-05 · 범위: `web/` 작업 공간(`/workspace`) 화면만. 서버·API·DB 변경 없음.

## 1. 왜

- 피드백: 7일 동안 빡세게 굴리는 컨셉인데 작업 화면이 너무 차분하다. 랜딩(검정·heat 주황·카운트다운)과 앱(흰 바탕·회녹색·라임)이 딴 제품처럼 끊긴다.
- 사용자 진단: 버튼이 많고 화면이 쪼개져 홈에서 무엇을 눌러야 할지 망설여진다.
- 현재 상태(코드 기준): 사이드바 메뉴 7개(프로젝트 업무·내 할 일·스프린트 현황·프로젝트 문서·팀·공수·변경안 검토·완주 확인), 상단 버튼 4개(새로고침·초대하기·내보내기·체크인). '프로젝트 업무'와 '내 할 일'은 필터만 다른 같은 표이고, 공수는 두 메뉴에 나온다. 매일 하는 체크인이 작은 버튼 중 하나다.

## 2. 성공 기준

- 홈에 들어오면 남은 시간·병목·팀 상황이 한 화면에 보이고, 누를 곳은 '진행 보고' 하나가 가장 눈에 띈다.
- 메뉴 3개(홈·업무·프로젝트), 상단은 카운트다운과 '진행 보고'뿐.
- 다크가 기본이고 라이트로 전환할 수 있다. 랜딩과 같은 색 언어.
- 움직임은 실제 상태(남은 시간, 지금 위치, 병목 발생)를 보여줄 때만 쓴다. 움직임 줄이기 설정이면 꺼진다.
- 기존 기능은 하나도 사라지지 않고 위치만 옮긴다. 서버 동작·권한·저장 흐름은 그대로다.

## 4. 테마

- **전환 방식**: `<html>`의 `.dark` 클래스 하나. shadcn이 이미 `@custom-variant dark (&:is(.dark *))`를 쓴다. 새 의존성 없음(next-themes 쓰지 않음).
- **처음 보일 모드**: `app/layout.tsx` `<head>`의 인라인 스크립트가 그리기 전에 `localStorage['pm-theme']`를 읽어 `light`가 아니면 `.dark`를 붙인다. 저장소 접근이 실패하면 다크. `<html suppressHydrationWarning>`.
- **전환 버튼**: 사이드바 아래 로그아웃 옆 해/달 아이콘 버튼. 값은 그 브라우저에만 저장한다(서버 DB 저장 안 함).
- **색 체계**(`app/globals.css`):
  - `--gray-*`: 회녹색 → 차가운 무채색. `.dark`에서는 단계를 뒤집는다(`gray-0` = 라이트 `#ffffff`, 다크 `#0b0b0c`; `gray-900` = 라이트 `#121212`, 다크 `#f4f2ee`).
  - `--green-*` → `--heat-*`로 이름을 일괄 변경하고 랜딩 heat 주황(`#ff5a1f`) 단계로 바꾼다.
  - 상태색: 위험 빨강(`#ff3b30` 다크 / `#e5281b` 라이트), 완료 초록 하나. 기존 `--orange-*`, `--red-*`는 이 둘과 heat로 정리한다.
  - shadcn 의미 변수(`--background`, `--primary` 등)는 위 단계를 가리키게 `:root`와 `.dark`에 정의한다.
  - 직접 적힌 색 값 38곳(`globals.css` 토큰 정의 이후)을 변수로 바꾼다.
- **라이트 모드 상단 바**는 검정(시안 B). 다크에서는 바탕과 같은 톤에 아래 경계선.
- **형태**: 모서리 반경 12/8px → 6/4px. 큰 숫자는 굵은 고정폭(`--font-geist-mono`), `tabular-nums`.
- **랜딩**: `.rl` 아래 자체 변수라 영향 없음. `body:has(.rl)` 배경 규칙 유지.

## 5. 화면 구조

### 5.1 메뉴와 주소

| 새 메뉴 (`?view=`) | 옮겨오는 것 |
|---|---|
| 홈 `home` | 스프린트 현황(`today`), 팀·공수(`team`)의 공수 표, 메이트 카드(병목 알림 한 줄로 축소), 회의 제안, 최근 체크인 |
| 업무 `tasks` | 프로젝트 업무(`plan`), 내 할 일(`mine` → '내 것만' 토글), 변경안 검토(`ai` → 업무 화면 버튼) |
| 프로젝트 `project` | 프로젝트 문서(`docs`), 팀원·초대, 완주 확인(`result`), 내보내기, 참여 중단 |

- 기본 메뉴는 `home`.
- 예전 `?view=` 값은 새 메뉴로 연결한다: `today`·`team` → `home`, `plan`·`ai` → `tasks`, `mine` → `tasks` + 내 것만 켜짐, `docs`·`result` → `project`. 변환은 `workspaceViews` 옆 작은 대응표 하나로.
- `navigator.modelContext`에 등록한 화면 이동 도구(`app/workspace/page.tsx`)는 `workspaceViews`에서 목록을 만들므로 새 3개로 자동으로 바뀐다.

### 5.2 상단 바 (모든 메뉴 공통)

- 왼쪽: 프로젝트 이름 + `DAY n / 7 · 상태`.
- 오른쪽: 카운트다운(6절) + **진행 보고** 버튼(heat 주황, 둥근 알약형, 은은한 퍼짐 효과).
- 새로고침 버튼 삭제 → 창이 다시 보일 때(`visibilitychange`) 자동 재조회. 초대하기·내보내기는 프로젝트 메뉴로 이동.

### 5.3 홈

진행 중일 때 위에서 아래로:

1. **큰 숫자 3개**(7.1절).
2. **Day 트랙**(6.2절). 기존 '일차별 마감'을 바꾼 것.
3. **병목 알림 한 줄**: 배치 불가 업무가 있으면 빨간 띠로 "'업무명'(담당)이 마감 안에 배치되지 않아 …" + `업무에서 조정 →`(업무 메뉴로 이동). 없으면 표시하지 않는다. 기존 메이트 카드의 문구(목표 축소·기한 연장 대신 재배정·순서·방법 변경)는 여기 보조 문장으로 남긴다.
4. **팀 레인**: 사람마다 한 줄. 지금 붙잡고 있는 업무(진행 중 상태 업무, 없으면 완료 안 된 첫 업무)와 마감, 필요/예산 공수 막대(`plan.perPerson`). 내 줄 강조, 예산 초과면 막대 빨강.
5. **회의 제안**, **최근 체크인**: 기존 패널을 아래로 옮긴다(내용 변경 없음).

- **시작 전(draft)**: 1~4 대신 기존 '목표 재동의'와 '시작 준비' 패널, 그 아래 `스프린트 시작` 버튼 하나.
- **완주·기한 종료**: 큰 숫자와 트랙은 마지막 값으로 고정, 진행 보고 버튼 숨김.
- **업무 0개**: 큰 숫자 숨기고 "업무에서 업무와 담당자를 등록하세요" 안내 + 업무 메뉴 링크.

### 5.4 업무

- 기존 `TaskCollection`의 표/보드 전환, 상세 패널 유지.
- 상단 줄: `내 것만` 토글, `+ 업무`(팀장), `회의록으로 변경안 만들기`(누르면 같은 자리에 기존 `ChangeReview`가 열리고 닫으면 목록으로 돌아온다. 운영에서는 지금처럼 '준비 중').
- 병목 강조는 7.2절.

### 5.5 프로젝트

한 화면에 네 구역: ① 목표·결과물·완료 기준(`ProjectDetails`) ② 팀원과 초대(`TeamInvites`, 초대는 팀장만) ③ 완주 확인(결과물 근거·팀장 확인) ④ 기타(내보내기, 참여 중단).

### 5.6 진행 보고

- 기존 체크인 대화상자 재사용, 제목·버튼 이름만 '진행 보고'. 저장 동작(`mutate('checkin', …)`) 변경 없음.
- 열 때 내 업무 중 진행 중 상태를 우선 선택하고, 대화상자 안에서 다른 내 업무로 바꿀 수 있다(팀장은 전체 업무).
- 보고할 업무가 없으면 버튼 비활성 + 툴팁 "배정된 진행 중 업무가 없습니다". 완주·기한 종료면 숨김.

### 5.7 프로젝트 전환과 모바일

- 사이드바 맨 위 프로젝트 이름 드롭다운에 프로젝트 목록과 `+ 새 프로젝트`를 합친다.
- 모바일은 기존 shadcn 사이드바 시트 유지. 상단 카운트다운과 진행 보고는 항상 보인다. 375px에서 가로 스크롤 없음.

## 6. 시간 표시

### 6.1 서버 시각 훅과 카운트다운

- `web/hooks/use-server-now.ts`: `asOf`(서버 시각)를 받으면 `offset = Date.parse(asOf) - Date.now()`를 저장하고 1초마다 `Date.now() + offset`을 돌려준다. `asOf`가 바뀌면 다시 맞춘다.
- 카운트다운 표기 `HH:MM:SS`(총 시간, 랜딩 `167:59:52`와 같은 형식). 0 아래로 내려가지 않는다.
- 색 단계: 남은 시간 > 72h 기본 글자색, ≤ 72h heat 주황, ≤ 24h 빨강 + 느린 깜빡임.
- 상태별: 시작 전 `7일 · 시작 전`(흐리게), 완주 `완주`(멈춤), 기한 종료 `00:00:00 · 기한 종료`.
- 0에 도달해도 화면이 스스로 종료로 바꾸지 않는다. 재조회를 한 번 호출하고 서버가 알려준 상태를 따른다.
- `role="timer"`(기본 `aria-live` off)로 매초 낭독하지 않는다.

### 6.2 Day 트랙

- `deadline-calendar.tsx`의 기존 `past`/`today` 구분 위에 모양만 바꾼다: 지난 날 heat 옅게, 오늘 heat 꽉, 남은 날 비움.
- 오늘 칸 안에 하루 중 현재 위치 세로 막대(같은 훅 사용, 깜빡임).
- 승인된 업무 마감 목록은 그대로. 예상 완료는 싣지 않는다. 배치 불가 업무에는 빨간 깃발.

## 7. 병목과 큰 숫자

### 7.1 큰 숫자 3개

`web/lib/sprint-pulse.ts`의 순수 함수 `sprintPulse(tasks, plan)`:

| 숫자 | 계산 | 표시 |
|---|---|---|
| 완료 업무 | 완료 수 / 전체 수 (`deferred` 제외) | `4/7` |
| 공수 | `plan.needed - plan.available` | 양수 `+9h 초과`(빨강), 0 이하 `12h 여유` |
| 병목 | `plan.unscheduled.length` | `1건`(빨강), `0건`(초록) |

시간 기준 완료율(%)은 쓰지 않는다. 처음 추정치를 저장하지 않아 정직하게 계산할 수 없다.

### 7.2 병목 강조

- 판별: `!t.done && !plan.finishes[t.id]`(지금 화면과 같은 조건).
- 업무 표·보드: 빨간 왼쪽 띠 + `병목` 태그.
- 움직임: 병목이 새로 나타날 때 한 번만 옆으로 밀렸다 돌아온다(반복 없음). 이전 렌더의 병목 id 집합과 비교한다.
- 마감 지난 업무(`schedule-warning`) 주황 → 빨강. 담당자 공수 막대 초과 시 빨강.

## 8. 움직임 원칙

- 지속 움직임은 세 가지뿐: 카운트다운 숫자, 오늘 위치 막대 깜빡임, 진행 보고 버튼 퍼짐. 24시간 이하 카운트다운 깜빡임이 네 번째.
- 일회성: 병목 등장 밀림, 화면 진입 시 큰 숫자 페이드업(0.3s).
- 시간: 150~300ms, `cubic-bezier(0.2, 0.8, 0.2, 1)`(랜딩과 같은 곡선).
- `@media (prefers-reduced-motion: reduce)`에서 모든 애니메이션 끔. 색과 숫자 변화는 유지.

## 9. 바꾸지 않는 것

- 서버, API, DB, 권한 검사, 버전 충돌 처리, 저장 트랜잭션.
- 각 패널의 내용과 문구(목표 합의, 초대, 변경안 검토, 결과물 근거). 위치만 옮긴다.
- 랜딩, Python 엔진.

## 10. 검증

- 단위 테스트: `sprintPulse`(업무 0개, 전부 완료, 초과, 여유, 배치 불가, 보류 제외), `useServerNow`의 시각 보정 계산(순수 함수로 분리해 테스트), 카운트다운 색 단계 경계(72h·24h), 예전 `?view=` → 새 메뉴 대응.
- 기존 테스트 갱신: `tests/meeting-panel.test.mjs`는 7개 view id와 `tab === 'today'` 블록을 단언한다 → 새 id(`home`·`tasks`·`project`)와 홈 블록 기준으로 바꾼다. 회의 제안 패널이 홈에 남는다는 의도는 유지.
- `npm test`, 타입 검사, `npm run lint`, `npm run build` 통과.
- 브라우저 확인(로컬): 브라우저는 개발 헤더(`oai-authenticated-user-*`)를 스스로 붙이지 않으므로, 로그인된 화면을 띄우는 방법(헤더를 붙이는 개발용 경로 또는 실제 Google 로그인)은 구현 계획에서 정한다. 확인 대상: 진행 중 프로젝트를 다크·라이트 각각, 시작 전·완주 상태, 375px 폭, 움직임 줄이기 설정. 화면 사진 첨부.
- 저장 후 재조회: 진행 보고 저장 → 큰 숫자·레인·트랙 갱신 확인. 계정 분리: 팀원 계정에서 `+ 업무`·초대가 보이지 않음.
- 단위 테스트 통과를 "덜 망설인다"는 사용 효과로 말하지 않는다. 그건 팀원 사용 관찰로만 확인한다.
