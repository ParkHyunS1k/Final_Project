# ProjectMate 공개 업무 기록 평가 데이터셋 v1

공개 GitHub 원문을 사용한 50건의 초기 평가 자료다. 한국어 40건, 영어 10건이며, 46개 저장소의 서로 다른 이슈 50개에서 수집했다. 댓글 사례 38건, 문서형 이슈 본문 사례 12건이다. 여러 발언을 함께 담은 사례를 포함해 원문 발췌는 57개다. 수집일은 2026-09-08이다.

**직접 만든 합성 시나리오는 0건이다. 원문에 단어·설명·문장부호를 추가하거나 수정하지 않았다.** 번역, 맞춤법 교정, 문장 완성, 공백 정리, 유니코드 정규화도 하지 않았다. 짧은 연속 구간을 선택하는 발췌만 수행했다. 서로 떨어진 구간이나 서로 다른 댓글은 별도 객체로 보존했다.

## 파일

| 파일 | 용도 |
|---|---|
| [dataset.jsonl](dataset.jsonl) | 실제 원문과 출처. 한 줄이 사례 1건이며 ID 순서와 줄 번호가 같다. |
| [annotations.jsonl](annotations.jsonl) | AI가 작성한 분류·기대 해석·금지 동작. 원문과 분리했으며 사람 검수 전이다. |
| [review.md](review.md) | 50건의 검토용 설명과 실제 출처 링크. 설명은 원문 인용이 아니다. |
| [review.html](review.html) | 원문과 라벨을 나란히 보는 로컬 검토 화면. 두 JSONL 파일을 직접 선택해 열 수 있다. |
| [splits.json](splits.json) | 저장소 단위로 분리한 개발용 35건 / 보류 평가용 15건. |
| [verification.json](verification.json) | 수집 당시 GitHub API 원본 필드와 제목·발췌의 문자 단위 일치 검사 결과. |
| [manifest.json](manifest.json) | 건수, 구성, 파일 해시. |
| [validate.py](validate.py) | 건수·중복·해시·발췌 범위·분할 검증. 표준 Python만 사용한다. |

## 원문과 해석의 경계

`dataset.jsonl`의 `input.thread_title_at_collection`과 `input.excerpts[].text`는 GitHub API 필드에서 그대로 복사한 문자열이다. 각각의 출처 API URL, 원문 필드명, 문자 범위 `[start, end)`, 발췌 SHA-256, 전체 필드 SHA-256을 기록했다. 문자 범위는 Python 문자열 인덱스이며 UTF-8 바이트 오프셋이 아니다. JSON 안의 `\r\n` 등은 원래 문자를 보존하기 위한 직렬화 표현이다.

`annotations.jsonl`은 전부 AI가 작성한 해석이다. `review_status=not_human_reviewed`이므로 확정 정답(gold label)으로 취급하지 않는다. `expected`에 없는 수치와 날짜는 추정하지 않는다. 원문에 없는 잔여 시간은 `remaining_minutes=null`이며, 0시간을 의미하지 않는다. 해석은 전체 스레드가 아니라 제공된 발췌 범위에 한정한다.

확인 가능한 원문을 짧게 제공하기 위해 **각 이슈의 제목과 모든 발췌를 합쳐 공백 기준 25단어 이하**로 제한했다. 따라서 이 자료는 장문 전체 맥락 이해 평가가 아닌 짧은 업무 발언·문서 항목 추출 평가용이다. 전체 대화는 각 사례의 출처 링크에서 확인할 수 있다. 발췌에서 빠진 사실을 모델의 누락으로 채점하면 안 된다.

## 수집 방법

1. 일반 웹 검색으로 공개 개발 기록을 탐색했다. 최종 채택한 50건은 모두 GitHub 공개 이슈·댓글이다. Reddit 검색 결과는 최종 데이터에 포함하지 않았다.
2. GitHub REST 검색으로 진행 보고, 완료, 계획, 미구현, 중복, 예상·잔여 시간을 포함한 후보를 찾았다. 실제 검색식은 각 사례의 `provenance.discovery_query`에 남겼다.
3. 이슈 본문은 검색 API 응답, 댓글은 댓글 API 응답에서 직접 읽었다. 검색 결과 요약문을 원문으로 사용하지 않았다.
4. 같은 내용을 반복해서 50건으로 늘리지 않고 서로 다른 이슈 50개를 선정했다. 같은 저장소의 이슈가 여러 개면 개발/평가 분할에서 같은 쪽에 배치했다.
5. 선택한 모든 제목·발췌를 API 문자열과 직접 비교했다. 원문에 없는 문장을 보충한 사례는 없다.

명시적인 `Bot` 계정은 배제했으며 채택된 발췌의 계정 유형은 모두 GitHub `User`다. 다만 `User` 계정이라는 사실만으로 사람이 직접 쓴 글인지, 작성자가 AI 도움을 받았는지까지 확인할 수는 없다. 탈퇴 계정의 `ghost` 표시도 원본 그대로 남겼다. **공개 실재 게시물이라는 점을 확인한 것이며 인간 작성 여부를 독립 인증한 자료는 아니다.**

## 포함한 판단 상황

- 진행 중, 직접적인 완료 보고, 부분 완료, 아직 배포하지 않음, 아직 푸시하지 않음.
- 브랜치 생성이나 PR 요청에 대한 완료 응답을 기능 전체 완료로 오인하는 경우.
- 담당 의사, 명시된 담당자·기한, 조건부 작업, 선행 조건, 보류 이후 완료.
- 다른 이슈에서 작업하겠다는 발언, 중복 관계 보고, 중복인지 묻는 질문.
- 여러 업무의 서로 다른 상태, 구현 요구사항과 실제 장애 보고 구분.
- 총 예상 공수와 잔여 공수 구분, 서로 충돌하는 예상 공수 표기.
- 제품 화면에 표시할 시간을 개발자의 남은 공수로 혼동하는 경우.
- 상시 규칙을 지금 실행할 구체적인 업무로 오인하는 경우.

PM-REAL-038은 잔여 시간 280분이 명시되어 있다. 서비스의 30분 단위 입력 제한과 충돌하더라도 원문이나 라벨을 반올림하지 않았다. PM-REAL-048은 원문 안의 예상 시간 두 값이 충돌하므로 하나를 정답으로 선택하지 않았다. PM-REAL-049의 값은 총 예상 시간이고 잔여 시간은 아니다.

## 현재 자료로 평가할 수 없는 부분

모든 사례에서 **변경 직전 ProjectMate DB 상태와 멤버 권한 정보는 알 수 없다.** `prior_project_state`와 `member_directory`를 `null`로 두었고 기존 업무 목록·담당자 매핑·기존 공수를 만들어 넣지 않았다. 따라서 `automatic_db_mutation_gold`도 모두 `null`이다.

이 자료로 업무 발언 해석, 상태 구분, 명시된 참조 대상 추출을 시험할 수 있다. 하지만 실제 서비스의 잘못된 업무 수정률·중복 생성률·안전한 자동 반영률을 완전히 측정할 수는 없다. 이를 평가하려면 이후 파일럿에서 입력 직전 DB 스냅샷과 사람이 승인한 변경 결과를 별도로 수집해야 한다.

GitHub 제목과 본문은 수집 시점의 스냅샷이다. `created_at`은 게시물 생성 시각이며 현재 본문의 최초 작성 시각이라고 보장하지 않는다. `updated_at`도 보존했으나 과거 편집 버전은 복원하지 않았다. 이슈가 지금 열림/닫힘인지, 현재 담당자가 누구인지 등의 상태는 과거 대화의 정답으로 넣지 않았다.

선별한 공개 개발 이슈에 편향되어 있고 개인 메신저·비개발 직군 대화를 대표하지 않는다. 명시적 잔여 공수 사례는 1건뿐이므로 잔여 시간 추출 성능을 일반화할 수 없다. 공개 자료가 모델의 사전학습에 포함되었는지도 알 수 없다. 보류 평가용 분할은 우리 프롬프트 튜닝에서 보류한다는 뜻이며 모델이 한 번도 보지 않은 데이터라는 뜻은 아니다.

## 사용 및 검증

먼저 `review.html`이나 `review.md`에서 사람이 라벨을 확인한다. 이후 `splits.json`의 개발용 사례로 프롬프트를 조정하고 보류 평가용 사례는 마지막 비교에 사용한다. 모델에는 원문 입력만 제공하고 `annotations.jsonl`의 해석·정답 후보는 제공하지 않는다.

```python
import json
from pathlib import Path

root = Path("datasets/public-task-extraction-50-v1")
records = [json.loads(line) for line in (root / "dataset.jsonl").read_text().splitlines()]
for row in records:
    model_input = {
        "thread_url": row["input"]["thread_url"],
        "thread_title_at_collection": row["input"]["thread_title_at_collection"],
        "messages": [
            {key: excerpt[key] for key in ("text", "author_login", "created_at", "updated_at")}
            for excerpt in row["input"]["excerpts"]
        ],
        "prior_project_state": None,
        "member_directory": None,
    }
```

```sh
python3 datasets/public-task-extraction-50-v1/validate.py
```

기본 검증은 배포된 파일의 무결성을 검사한다. 인터넷의 원문이 현재도 같은지는 재조회하지 않는다. 수집 당시 원문 일치는 `verification.json`에 기록했다. 원문이 이후 수정되면 기존 오프셋과 전체 필드 해시가 달라질 수 있다.

원문 자료의 권리를 별도로 확보했거나 공개 글 전체를 재배포 가능한 라이선스로 확인한 데이터셋은 아니다. 출처를 유지한 짧은 발췌 자료이며, 공개 재배포·모델 학습용 말뭉치로 전환할 때는 해당 이용 범위를 별도로 확인해야 한다.
