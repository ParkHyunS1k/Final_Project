# API 키 없는 Luna low 첫 평가

**기존 ChatGPT 로그인으로 실제 실행했다.** GPT-5.6 Luna / reasoning effort `low`에 개발용 사례 35건을 각각 독립적으로 입력했다. 35건 모두 JSON 스키마에 맞는 응답을 받았다. 모델의 도구 호출과 서비스 DB 변경은 없었다. 보류 평가용 15건은 실행하지 않았다.

이번 결과는 작은 모델의 초기 가능성과 실패 유형을 확인하는 시험이다. 사람 검수 정답으로 계산한 정확도나 실제 운영 자동 수정 성공률은 아니다.

## 실행 조건

| 항목 | 실제 설정 |
|---|---|
| 실행일 | 2026-09-08 |
| 클라이언트 | Codex CLI 0.145.0 |
| 요청 모델 | `gpt-5.6-luna` |
| 추론 강도 | `low` |
| 인증 | `codex login status`에서 확인한 기존 ChatGPT 로그인 |
| API 키 | 별도 키 미사용. 실행 환경에서 OPENAI_API_KEY / CODEX_API_KEY 제외 |
| 입력 | 원문 제목·발췌·작성자·시각만 전달. AI 해석 라벨 미제공 |
| 호출 방식 | 사례마다 새 임시 세션. 1건 확인 후 나머지 34건 실행, 최대 동시 실행 3개 |
| 작업 디렉터리 | 데이터셋·정답 파일이 없는 별도 임시 디렉터리 |
| 도구 | 셸·브라우저·앱·플러그인·다중 에이전트 등을 비활성화. 실제 도구 호출 0건 |
| 프롬프트 수정 후 재시도 | 없음. 최초 응답을 그대로 기록 |

[공식 인증 문서](https://learn.chatgpt.com/docs/auth)는 ChatGPT 로그인과 API 키 로그인을 구분한다. [공식 모델 문서](https://learn.chatgpt.com/docs/models)는 Luna를 추출·분류 등 명확하고 반복적인 작업용 모델로 설명한다. 이번 실행은 구독에 포함된 Codex 사용량을 쓴 로컬 평가이며, 웹 서비스가 일반 OpenAI API를 구독 토큰으로 호출하도록 연결한 것은 아니다.

## 자동 검사 결과

| 지표 | 결과 |
|---|---:|
| 정상 실행 및 스키마 검증 | 35 / 35 |
| 사전에 정한 일부 검사 모두 통과 | 32 / 35 |
| 개별 검사 통과 | 173 / 177 |
| 모델 도구 호출 | 0 |
| 보류 평가용 실행 | 0 / 15 |
| CLI 실행시간 중앙값 | 약 9.0초 / 건 |

32/35는 **선택한 검사 항목의 통과 건수**다. 이를 91.4% 정확도라고 부르면 안 된다. 검사가 모든 업무 누락·대상 혼동·환각을 포괄하지 않으며, 아래처럼 통과 사례에서도 추가 검토 사항이 나왔다. PM-REAL-001은 첫 연결 확인 결과를 본 뒤 검사 기준을 기록했고, 나머지 기준은 일괄 실행 결과를 읽기 전에 기록했다. 기준은 [rubric.json](rubric.json)에 보존했다.

## 확인된 문제와 데이터 한계

| 사례 | 실제 응답에서 확인한 점 | 영향 / 판정 |
|---|---|---|
| [PM-REAL-038](results/PM-REAL-038.json) | 요약은 총 280분이라고 했지만 마스크·리깅·텍스처 세 항목에 각각 280분을 넣었다. | 명확한 구조화 오류. 그대로 합산하면 840분이 된다. 합계 공수와 항목별 공수를 구분해야 한다. |
| [PM-REAL-043](results/PM-REAL-043.json) | 설명에는 API 완성 이후라는 조건을 유지했지만 modality 필드는 asserted로 출력했다. | 설명과 구조화 필드 불일치. 자연어 요약만 보고 성공 판정할 수 없다. |
| [PM-REAL-048](results/PM-REAL-048.json) | 시간 선택 체크박스를 작업 완료 표시로, 폼의 라벨 영역을 별도 업무로 해석했다. | 데이터 발췌와 모델 해석을 함께 검토해야 한다. 아래 설명 참조. |

| [PM-REAL-024](results/PM-REAL-024.json) | 설명에는 전체 완료 여부가 불명확하다고 쓰면서 whole_thread_completion_reported는 true로 출력했다. | 자동 검사 통과 사례지만 응답 내부에 모순이 있다. 구조화 값과 설명을 함께 검토해야 한다. |

**PM-REAL-048은 수집·라벨 작성 과정의 문제도 발견했다.** 첫 발췌에서 예상 시간 섹션 제목을 제외한 탓에 모델에게 주어진 텍스트만으로 해당 체크박스가 공수 선택란인지 확실하게 알 수 없다. 반면 기존 라벨은 전체 원문을 보고 공수 충돌이라고 판단했다. 이는 입력보다 라벨이 더 많은 맥락을 가진 사례이므로, 모델의 확정 오답으로 집계하면 부당하다. 다음 데이터 버전에서는 원문 섹션 문맥을 추가하고 라벨을 재검수해야 한다. 이번 원문·라벨·출력·자동 점수는 사후에 유리하게 바꾸지 않고 그대로 남겼다.

일부 응답은 한 업무의 이전 보고와 최신 보고를 여러 work_items로 반환한다. 현재 결과는 해석 후보이며, 목록의 각 항목을 그대로 신규 업무 생성이나 현재 업무 상태 변경으로 실행하면 안 된다. 실제 적용을 위해서는 기존 업무 ID 매핑, 변경 종류, 공수 적용 범위, 승인·권한 검사가 추가로 필요하다.

## 잘 처리한 범위

이번 표본에서는 PR 요청에 대한 완료와 전체 기능 완료 구분, 다른 이슈에서 작업한다는 참조, 배포 전·푸시 전 상태, 구현 완료와 문서 작업 진행 중의 구분, 중복 확정과 중복 질문의 구분이 확인됐다. 총 예상 공수와 잔여 공수 구분도 일부 사례에서 가능했다. 각 사례의 실제 응답은 [results](results) 아래에 있다.

**Luna low를 업무 추출·수정안 초안 생성에 시험 적용할 근거는 생겼다. 무검토 자동 DB 수정이 충분히 안전하다는 근거는 아직 없다.** 다음 비교는 원문의 문맥과 출력 스키마를 보완한 새 버전에서 동일 모델을 다시 평가한 뒤, 같은 조건으로 상위 모델과 비교하는 순서가 적절하다.

## 토큰과 사용량

CLI가 보고한 35회 합계:

- 입력 토큰: 275,228
- 캐시 입력 토큰: 82,944 — 입력 토큰 중 캐시된 부분이며 별도로 더하지 않는다.
- 출력 토큰: 10,759
- 추론 출력 토큰: 3,544 — CLI가 별도 보고한 값으로 보존하며 총량에 재합산하지 않았다.

호출당 약 7,800개의 입력 토큰에는 Codex의 기본 지침과 JSON 스키마 등 실행 환경 비용이 포함되어 있다. 이 수치와 약 9초의 실행시간은 일반 API로 동일 기능을 구현했을 때의 토큰·가격·지연시간을 뜻하지 않는다.

계정 전체 사용량은 시험 전 단기 75% / 주간 12%, 35건 완료 직후 단기 94% / 주간 15%로 조회됐다. 이는 이 대화와 다른 동시 사용을 포함할 수 있는 계정 전체 수치이므로 증가분을 시험 호출에만 귀속하지 않는다. 단기 잔여량을 고려해 추가 모델 호출은 실행하지 않았다.

```sh
# 모델을 호출하지 않고 저장된 응답을 다시 검사
python3 evals/public-task-extraction/luna-low-2026-09-08/score.py
```

계정 사용량을 사용하는 재실행은 `run.py --development`로 할 수 있다. 현재 폴더에서는 기존 성공 응답을 재사용한다. 프롬프트·모델·스키마를 바꾸어 비교할 때는 새 실행 폴더를 사용하고 이 기준 결과를 보존한다.
